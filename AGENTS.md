# Маршрутизация агентов для публичного knowledge (сверка 23.11.2026)

Этот репозиторий содержит **разные** исходные направления: `packages/t3-core` — **один исполняемый T3**, наследующий оригинальный T2; `packages/t4-network` — сетевой T4; каталог специализированных агентов и исследования Mesa/АКИС — отдельные области. Применять нижестоящие правила **по конкретной области**, а не объявлять весь репозиторий исключительно каталогом специализированных агентов. `Faust-S/T3` остаётся оригинальным приватным владельцем подписанных Access/Ed25519/issuer/license/DPAPI и закрытых доказательств; публичный knowledge не становится вторым издателем подписанта. Ни публичные, ни частные исследования не создают второй Kernel/Host/Store/Task Engine/Exchange/`.iwxa`. Действующие доказательства выпуска T3 находятся в `packages/t3-core/handoff/G4_PRODUCT_RELEASE_EVIDENCE_CURRENT.json`, **не** в факте наличия source или PASS одного набора. Приватные Actions запрещены; публичные CI в knowledge возможны по отдельному поручению. Научную АКИС/Mesa не считать автоматически принятой промышленной системой.

**ПРИОРИТЕТНОЕ РЕШЕНИЕ ВЛАДЕЛЬЦА 21.11.2026 — ОДНА ЦЕЛАЯ КОРПОРАТИВНАЯ WORKSPACE:** Единицей работы, сохранения и передачи компании является **только вся исходная T2 Workspace**, открытая сотрудником по подписанному корпоративному полномочию. Всё, что пользователь создаёт в выбранной Workspace, принадлежит ей с момента создания; Agent не формирует отдельный корпоративный Result, экспорт выбранных Task/документов, вторую WorkArea/Store или мосты сохранения по типам записей. Корпоративный `.iwxa` — полный штатный экспорт **одной выбранной корпоративной Workspace** с историей, связями, Asset и схемами через оригинальный T2 Exchange (`t2.exportPackage`), без переключателей исключения частей. Личная Workspace и чужие организации никогда не входят. Получатель читает/импортирует весь пакет штатным T2; при офлайн-работе доступность компании наступает после реальной передачи, не после локального сохранения. Никаких дополнительных подтверждений состава Result: только стандартный Human Review там, где он уже требуется. Существующие проверки исходной Task/Result НЕ доказывают полного Workspace-export. Выпуск универсальной технологии T3 требует законченных D1-D7 на оригинальном T2 и воспроизводимого версионированного One Dist. Незаконченная привязка нативного Python Task Engine Agent к корпоративной Workspace и весь физический маршрут Agent → Admin Center являются отдельной обязательной приёмкой корпоративных приложений, а не блокером выпуска универсального T3. До корпоративного приёма не объявлять B2B-функции готовыми. `T3_READY=false`, `NOT_RELEASED`; не создавать новый Kernel, Store, Workspace, Exchange, Task Engine, IAM или `.iwxa`. Нормативные подробности в разделе 8 [архитектурного аудита](packages/t3-core/docs/T3_G4_ECOSYSTEM_RELEASE_READINESS_AUDIT_2026_11_19_RU.md). Предыдущие решения о выборочной передаче корпоративного Result и пообъектных мостах отменены.
