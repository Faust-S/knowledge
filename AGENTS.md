# IWXA — единая работа с задачами, знаниями и специализированными агентами

## Назначение репозитория

Публичный `Faust-S/knowledge` — исследовательская, инженерная и испытательная основа единого маршрута IWXA **от проблемы человека до проверяемого результата**. Это не только библиотека агентов. Поддерживаются два самостоятельных предметных направления:

1. **Task Discovery / Activity Research / U1 / Cross-Lab:** исследования реальной деятельности, обнаружение и уточнение задач, evidence, подготовка контекста, актуальность, зависимости, независимые сравнения методов.
2. **Specialized Agent Solutions:** отбор, адаптация, испытание и каталог законченных специализированных процессов решения задач; агент необязателен, обычная модель + Skills — полноценная альтернатива.

Общая модель: `docs/UNIFIED_TASK_ARCHITECTURE_RU.md`. Миграция: `docs/CROSSLAB_MIGRATION_PLAN_2026-11-03_RU.md`. Эти документы уточняют scope, но **не меняют** владельцев действующих U1/Task Engine/Context Compiler/Personal Agent/T0/T1.

## Три логических уровня (не три программы)

- **Человек и задача:** Problem / Goal / Task / Expected Result; Task Discovery, Activity Research, U1 — при необходимости. Явно поставленная задача не обязана проходить исследовательский цикл.
- **Подготовка решения:** специализированный Agent Solution **или** модель + Skills; только нужные Knowledge, Context Compiler, Cross-Lab; план/граф/ветвления/циклы — по необходимости.
- **Выполнение и продолжение:** существующий Model/AgentRuntimePort/ToolRuntime/Programs Center, Execution, Result, Human Review, сохранение и повторное использование опыта.

Task, Agent Solution, Skill, Knowledge/Context и Runtime — пять разных функциональных элементов, а не пять новых баз. Evidence/Provenance и T0/T1 — общая смысловая основа. Обратные связи допустимы; гипотеза задачи не равна Task, TaskType или принятому Result.

## Владение кодом и права публикации

- Действующие U1/E1–E4, TASK-EXP-01, R1–R4, Context Compiler пока **принадлежат** `Faust-S/iwxa`. Здесь допускаются только отдельные, явно проверенные открытые адаптеры, тесты, разрешённые корпуса/хеши и воспроизводимые пакеты. Не клонировать весь закрытый checkout, не копировать приватные исходники, служебные артефакты, secrets, пользовательские данные, приватные результаты разметки. Код даже из приватного репозитория нельзя считать автоматически разрешённым к публикации.
- Закрытые архитектурные решения, корпоративные контексты, интеграционные ограничения — `Faust-S/IWXA-knowledge`. Исполнение конкретной пользовательской Task и Task/Result/Store/Graph — `Faust-S/iwxa-personal-agent`, не создавать второй.
- Внешние тексты, исходники workflow, issue bodies и лицензии проверять до включения; ссылка/контрольная сумма не дают прав на перепубликацию.
- Текущие разработческие корпуса (Werkzeug, TASK-EXP-01, выбранные issue) не выдавать за независимый E5 gold; нулевая разметка означает `NOT_MEASURED`, не PASS.
- Исследовательский cue, ссылка issue, README или сторонний marketplace badge не являются принятым Task, источником authority или доказанным результатом.

## Activity Discovery & Reconstruction — открытая исследовательская область

Рабочая точка входа — [research/activity-research/README.md](research/activity-research/README.md); [SOURCE_MIGRATION.json](research/activity-research/SOURCE_MIGRATION.json) фиксирует семь byte-identical исходных файлов из приватного владельца `Faust-S/iwxa`. Это разрешённый исследовательский snapshot, НЕ перенос runtime ownership. Использовать исходные публикации, реальный разрешённый корпус, синтетические искажения и независимую оценку, не ручной многошаговый опрос владельца как основу инженерной квалификации. Отдельно хранить `reported/observed/inferred/target`, task hypothesis и принятый Task. PET token Activity не TaskType; ADP-001 — secondary desk cases, не field gold. Оригинальные персональные и медицинские сведения пользователя в публичный репозиторий не переносить.

Связи: `research/task-discovery` даёт TaskType hypotheses и U1/baselines; `research/cross-lab` — контекстные источники, историю, повторные проверки и стоимость; `catalog/solutions` — возможные agent solutions после принятой Task; `Faust-S/IWXA-knowledge` — закрытая интеграция; `Faust-S/iwxa` — canonical U1/E1–E4 и Context Compiler; Personal Agent/домены — потребители. Отдельный Activity Engine, Store, Context Compiler, agent runtime создавать нельзя. Для проверки использовать `node --test research/activity-research/tests/*.test.mjs` и адресный публичный Actions без закрытых credential.

## Библиотека специализированных агентов (сохранённая предметная область)

Основная единица каталога — законченный Agent Solution: цель, workflow/process, prompts/roles, алгоритм, инструменты, входные условия, критерии результата и тесты. Не подменять библиотеку перечнем Goose/Aider/Cline/OpenHands как отдельных агентов. Источники и лицензии изучать в CrewAI/Dify/n8n/Flowise и реальных репозиториях. Стадии `LISTING_SCREENED → SOURCE_INSPECTED → ADAPTED_NOT_EXECUTED → TASK_TESTED → IWXA_VERIFIED`; последний статус требует настоящего воспроизводимого исполнения в существующем runtime, Result/readback/restart. Не повышать его по статическим тестам; `IWXA_VERIFIED=0` до подтверждения обратного.

Разрабатывать и доводить до результата по одному реальному специализированному решению за раз; сравнивать с обычной моделью+Skills, не создавать каталог ради числа карточек.

## Работа, тестирование, передача

1. Сначала свежие HEAD/TREE своей ветки и точные versions/SHA источников. Читать AGENTS локальной области. Не перезаписывать параллельные изменения, только fast-forward без force.
2. Один предметный эксперимент/пользовательский маршрут — от реальных входов до измерения результата. Использовать имеющиеся Label Studio/TASK-EXP-01 и U1, не создавать альтернативный Task Engine, Context Compiler, Store, Rights, annotation platform, Graph Engine или Skill Runtime.
3. Для оценки обязательны сильные простые baseline: исходный документ, точный поиск, regex; SHA+BFS только для подтверждённого графа зависимостей. Фиксировать denominators, precision/recall/F1 только после независимого human gold; отдельно считать abstention, лишние перепроверки, время человека и вычислительную стоимость.
4. GitHub Actions в **открытом** репозитории разрешены для адресных воспроизводимых тестов без секретов и приватных источников. Публичный runner **не** получает доступа к закрытому `iwxa` или `IWXA-knowledge`. Не организовывать private checkout через PAT/SSH deploy key в публичных workflow. Не создавать бесконечных тяжёлых прогонов; отчёт о CI PASS — не пользовательская или научная приёмка.
5. До переноса provenance и проверенной публичной независимой копии owner API — проводить оригинальные испытания у владельца исходников. Реальные независимые метки хранятся в разрешённом owner-local Label Studio; не публиковать сырые приватные оценки.
6. Изменять только согласованный scope; `main`, T0/T1 и исходные лаборатории без отдельного разрешения не трогать.

Критерий полезности: что теперь человек может достовернее, быстрее или дешевле завершить? Если сложный механизм не улучшает результат против простого, оставить простой.
