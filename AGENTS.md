# Правила разработки IWXA Verified Agents

Работа пользователя определила новое назначение проекта: **реальная библиотека проверенных агентов**, без отдельной базы общих знаний, O*NET/ОКЗ пакетов, 12 баз и 4 видов пакетов. В пользовательском интерфейсе не вводить второй Programs/Skills/Agents catalog.

Начать с официального upstream агента и его exact source commit, подтверждённых README и license; источник в catalog — не рабочая интеграция. Для статуса IWXA_VERIFIED обязательны запуски с реальной моделью/инструментами, наблюдаемым результатом, отрицательные проверки прав и воспроизводимость в действующем Personal Agent. До этого сохранять SOURCE_SCREENED или ниже. Никогда не присваивать фальшивый готовый статус из unit tests.

Собирать по одному агенту, не массово генерировать «agent recipes». Обычная модель с инструментами — допустимое решение задачи, не объявлять провалом библиотеки. Нельзя использовать пользовательские данные или приватные исходники IWXA в публичном репозитории. Приватная оценка и решения в Faust-S/IWXA-knowledge; код и публично разрешённые квитанции здесь.

Не создавать новый Core, Store, AgentRuntimePort, ToolRuntime, task discovery, U1, Context Compiler или IWXA capability registry. Personal Agent ограничивает Goose PUBLIC/SYNTHETIC proposal-only; остальные adapters NOT_IMPLEMENTED. Подключать через проверенный публичный интерфейс только при соответствующем решении. Достоверность статусов важнее количества кандидатов.

Не запускать дорогие Actions / внешние сервисы без необходимости; обязательные локальные unit-тесты для metadata/gates. Ни один тест валидатора не равен тесту реального исполнителя.
