# Единая архитектура IWXA: пять элементов, три логических уровня

Статус: рабочая схема организации исследования и разработки от 03.11.2026. Не создание новой нормативной модели T0/T1, не объявление продуктового runtime PASS. Оригинальная концепция согласована с `Faust-S/IWXA-knowledge/docs/05_UNIFIED_TASK_TO_RESULT_MODEL_RU.md`; новая форма группировки уровней — организационное представление.

## Уровень 1 — Человек и задача

**Problem · Goal · Task · Expected Result.** Исходная проблема или цель → выявление возможных задач через существующие Task Discovery / Activity Research / U1, **когда требуется** → пользовательская Task: цель, желаемый результат, ограничения, критерий завершения. Для явно поставленной задачи discovery не обязателен. `Task instance ≠ TaskType`, гипотеза обнаружения не становится принятой задачей автоматически.

## Уровень 2 — Подготовка способа решения

**Agent Solution / модель + Skills · Knowledge · Context · Plan.** Специализированный агент — готовый процесс для подходящего класса задач, а не обязательный посредник и не название внешней программы. Обычная модель с Skills и инструментами — равноправная альтернатива, предпочтительна при сопоставимом качестве и меньших затратах. Knowledge, Context Compiler, Cross-Lab собирают только необходимые сведения и проверяют их актуальность, dependencies и provenance. Когда это полезно, план становится графом с шагами, ветвлением, ограниченными циклами, ожиданиями, retry и параллельностью. **Граф не обязателен.**

## Уровень 3 — Выполнение, проверка и продолжение

**Runtime · Execution · Result · Human Review · Memory.** Действующие Model Provider / AgentRuntimePort / ToolRuntime / программы выполняют работу. Результат должен соответствовать критериям, реально сохраняться и читаться повторно. Human Review применяется там, где нужна интерпретация или решение человека, а не только в конце; WAIT/обратный переход к уточнению Task, Context или Plan допустимы. Частичный результат и вопрос лучше ложного COMPLETED. Memory использует уже существующее хранилище/контекст пользователя, не превращает его документы в публичный каталог.

## Сквозные функции и владельцы

- **Пять функциональных ролей:** Task; Agent Solution (необязателен); Skill (по необходимости); Knowledge/Context (минимально достаточный); Runtime (существующий). Не означают пять новых баз.
- **T0/T1 · Evidence · Provenance:** семантика и подтверждение оснований для всех уровней; не самостоятельный пользовательский этап. Семантический граф T0/T1 и граф выполнения Personal Agent — разные сущности.
- **Исследовательское владение:** U1 / Task Engine / TASK-EXP-01, Cross-Lab R1–R4 / Context Compiler остаются в `Faust-S/iwxa` до подтверждённой передачи. Данные конкретного пользователя и жизненный цикл Task/Result находятся в `Faust-S/iwxa-personal-agent`.
- **Публичная инженерия:** открытые корпуса и метаданные, reusable agent solutions, сравнение методов, тестовые адаптеры — `Faust-S/knowledge`.
- **Закрытая интеграционная карта:** архитектурные решения, ограничения, связь лабораторий с продуктом — `Faust-S/IWXA-knowledge`.

## Наблюдаемый результат, а не видимость готовности

Технический проход U1/Cross-Lab ≠ повышение качества обнаружения Task. Слова в документе ≠ Task gold. YAML агента ≠ реальный агент; quote verified ≠ решение человека; готовая GraphDefinition ≠ исполненный граф. E5 `NOT_RUN`, независимая предметная оценка `NOT_MEASURED`; `IWXA_VERIFIED=0` для библиотеки до отдельных реальных испытаний.

Продуктовой интеграцией считать только Task → выбранный agent/model+skills → фактическое выполнение → Result с проверкой → сохранение/readback/restart. Исследовательские средства подключать по необходимости.
