# Activity + D05 CehoVod: исходные факты и оригинальный T3 D2

Источник модели: Faust-S/cehovod.ru, commit 0ada4f082a39ec9a7bf2be3f75b57ebc5ebc39b4, tree a0570f59cf74a4f6449d4cf874a288fc898fdc29.

В исходном оригинальном T2 Host домена CehoVod объявлены 26 типов Result версии 1.0.0 и ровно три типа Kernel-событий: cehovod.result.saved, cehovod.order.transitioned, cehovod.operation.transitioned.

Профиль d05-t3-evidence-binding.mjs передает этот список ОРИГИНАЛЬНОМУ D2 T3 0.3.0. Все три вида событий имеют epistemic_status=reported. Подписанная запись в Kernel не доказывает фактическую резку, гибку, измерение или приемку. Объекты типа operation остаются техническими Result, а не автоматически наблюденной Activity. Связи based_on берутся из оригинальных Kernel relations, строковые ID payload не превращаются в доказанные E2O-ребра.

В тесте test_activity_d05_t3_evidence.mjs использован модельный CASE-001 формата CehoVod с количеством 120 только как фикстура. Публичный CI проверяет зафиксированную структуру D05, действующий signed D1/D2 read, отказ после отзыва, привязку к Workspace, сохранность данных и HOLD для сообщенных этапов, редких связей и неизвестных событий.

Это НЕ свидетельствует о производстве 120 деталей, установленном оригинальном корпоративном Host в Activity, независимом подтверждении хозяйственных операций, анонимности, соответствии полному OCEL2 или разрешенном обмене .iwxa.

Для коммерческой квалификации требуется исполнить штатный CehoVod CASE-001 через оригинальный T2/Host с сохраненными результатами, актами и QC, подтвердить их независимым чтением и получить отдельную версионированную привязку истинно наблюдаемых бизнес-событий от владельца предметной системы. Activity не вправе самостоятельно повышать reported до observed.

Проверка полного совпадения с исходными TS-файлами D05 выполняется отдельно при явно предоставленном авторизованном локальном checkout через IWXA_D05_SITE_SOURCE_DIR. Публичный GitHub Actions не использует приватный D05 repo или токены. Статический pin не равен автоматически подтверждённой актуальности исходного сайта.

## Паспорт достаточности фактов в Activity

Доверенный T3 D1/D2 возвращает в существующий узкий React-порт только алиасы, статусы и разрешённые коды диагностик. В Activity добавлен пользовательский «Паспорт достаточности фактов» (`modules/activity-base-anonymizer/t3-evidence-passport.mjs`, `desktop/src/App.tsx`). Он не читает новый источник и не выполняет анализ повторно.

Паспорт отделяет два уровня: `INSUFFICIENT_FOR_RECONSTRUCTION` при `HOLD` и `INTERNAL_STRUCTURE_ONLY` для ограниченного структурного кандидата. Оба уровня **не доказывают фактическое исполнение или причинность**, не разрешают экспорт. Для каждого известного кода D2 выводятся адресный пробел и действие владельца предметной системы; вопросы сгруппированы по хозяйственным фактам, исходным связям, хронологии, рискам раскрытия и независимой квалификации. Первые два вопроса видны сразу, остальные раскрываются внутри того же интерфейса. Подтверждённое исключение `workspace.created` описывается отдельно как служебная очистка, а не ошибка. Никакой процент достоверности не вычисляется из количества кодов.

В модельном D05-кейсе штатные `cehovod.operation.transitioned` и `cehovod.result.saved` остаются `reported`, поэтому первый вопрос касается независимого подтверждения физической работы или QC. Оригинальная связь `based_on` сама по себе не разрешает раскрытие. Показатели времени и экономические потери будут вычисляться только после наличия проверенных исходных параметров, не из этого паспорта.

### Проверка паспорта на оригинальном T2 Kernel

Интеграционная квалификация [№45024738211](https://github.com/Faust-S/knowledge/actions/runs/45024738211), код `af8a974909f1aa64e617d83f6de4d6b4bb764d58`, дополнена непосредственным вызовом `buildT3EvidencePassport` после оригинального D1/D2 readback. Интеграционный тест **PASS**, журнал `ACTIVITY_D05_ORIGINAL_T2_SIGNED_REPORTED_COLD_HOLD_PASS` фиксирует `evidencePassport=true`. Паспорт выдаёт не менее двух адресных вопросов: неподтверждённое исполнение и оценка риска раскрытия связей. Исходные строки, ID, количество и исходные виды событий не попали в пользовательское представление. Право на экспорт не появилось.

Ни тестовый подписант, ни тестовый `iwxa.activity.d05.witness` не являются настоящим установленным корпоративным владельцем CehoVod. Следующий этап P1 не принимается только на основании этого теста.
