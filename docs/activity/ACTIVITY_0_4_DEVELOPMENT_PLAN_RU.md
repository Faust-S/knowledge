# IWXA Activity 0.4. План и первая реализация

База: release/0.3, bccd0fad3a1c97270b242ccb4c5e7ce7ec4183f3, установленная квалификация 45197570949. Релизную ветку не изменять.

## Целевой маршрут

Человек или организация -> разрешённые факты, модели и принятые результаты -> Activity: автоматизированное извлечение, содержательное обобщение и обезличивание -> готовый технологический продукт в оригинальном .iwxa -> независимый импорт, настройка и реальное использование получателем. Agent координирует подключённые инструменты и исполняет личные автоматизации. Домены выполняют предметные операции. Atlas планирует конкретные Work. Основные самостоятельные направления: организация → организация (предметная профессиональная технология) и человек → человек (личная технология для Personal Agent). Отдельную трансформацию организационного опыта в личную автоматизацию не разрабатывать. Профессиональное применение индивидуальным специалистом возможно в существующем предметном домене; оно не требует нового вида пакета. Не создавать ещё один графовый движок, Task Engine, IAM, Store, Core, Router, редактор BPMN, симулятор или формат .iwxa.

## Последовательность

- A4.1: локальное сравнение исходных моделей D05 и затем штатный доменный readback. Модели и исполнения не смешивать. В первой итерации использовать только существующий operation-route; схема данных определяется доменом.
- A4.2: приём результатов Rust4PM/Propel через действующие Agent ToolProviderPort и артефакты Workspace. Полная траектория/варианты, объектные связи, эпистемические статусы. Не использовать анонимные алиасы разных выборок как общую семантику.
- A4.3: переносимая технология с областью применимости, существенными требованиями, входами, выходами, ролями, критериями приёмки, различиями вариантов и ссылками на доказательства в исходной среде. Подтверждение предметным владельцем; стандартные BPMN/DMN через оригинальные инструменты Agent.
- A4.4: квалифицировать ARX для табличных обобщений, Presidio для текстов, OpenDP для допустимой агрегированной статистики. Проверить риск связывания графа и повторных публикаций. Измерять полезность обобщения и проверять полномочия отдельно.
- A4.5 (уточнённая цель владельца): формировать полноценный предметный технологический продукт с переносимыми инструкциями, условиями, критериями результата и адаптируемыми настройками. Внешнее моделирование необязательно и не является стадией Activity; при необходимости выполняется через Agent или домен.
- A4.6: использовать оригинальный Exchange T2/T3 для подтверждённого предметного профиля технологии. Не вводить новый формат или экспорт на основании одного UI-флага.
- A4.7: независимый импорт, адаптация получателем, планирование через Atlas при необходимости, исполнение доменом.
- A4.8: оценка фактической полезности (качество, затраты, длительность, повторное применение) с сопоставимыми базой и результатом.

## A4.1-I. Локальная группировка нормативных моделей

Семантика маршрутов сверена с разрешённым источником D05 (без публикации приватных исходников). Программа принимает существующий объект калькулятора operation-route или локальную копию его исходного Kernel Result. Это не доказательство полномочий, подписи, актуальной Workspace или физического исполнения.

Раздел «Группировка маршрутов» в «Реконструкция»: до 24 отдельных JSON-файлов общим объёмом до 8 МБ; 128 операций, 1024 зависимости на маршрут. Встроенные модели для первого запуска обозначены примером. Все вычисления происходят локально в существующем Activity; сырые записи не сохраняются. При смене раздела выборка очищается.

Группировка: точное название/тип, признак параллельности, контрольная веха, полный набор прямых зависимостей. Смена исходных ID и порядок записей не меняют группу; повторяющиеся смысловые пары требуют ручного сопоставления. Один ID маршрута не может увеличивать число моделей через разные редакции. Длительность, ресурсы, материалы, примечания и параметры маршрута сравниваются отдельно; индивидуальные значения не копируются в результат. Отсутствующие параметры явно отмечаются. Названия операций остаются в частной локальной карточке, поэтому внешняя передача запрещена.

Количество моделей не является числом независимых хозяйственных исполнений; равенство структуры не устанавливает эквивалентность технологии или пригодность к повторному использованию. A4.1-I не изменяет оригинальный D2, A2, T3 grants или IWXA Exchange.

Критерий текущего шага: тесты независимости ID, разных названий и связей, повторных редакций, циклов, конфликта форматов, несовпадений параметров, отсутствия экспорта; TypeScript, исходная квалификация на Windows/Linux, установленное Tauri и старые маршруты. Дальше: квалификация чтения настоящих сохранённых моделей D05 через разрешённый источник и сопряжение с Agent.

## A4.1-II. Точка вызова для параллельной разработки Agent

Опциональная локальная точка входа: tools/activity-d05-route-review.mjs. Не является отдельным приложением, механизмом обмена или программным владельцем Workspace. При наличии квалифицированной Node.js среды адаптер оригинального ToolProviderPort может вызвать Node с этим точным скриптом без shell, передав через stdin JSON-массив уже разрешённых существующих моделей operation-route (до 8 МБ). Аргументы пути/команды не принимаются. stdout содержит единственный JSON локального результата либо типизированный HOLD с кодом, без исходных ошибок/путей. Процесс не читает Kernel, сеть и файлы.

Результат совпадает с вычислением нативного интерфейса. Он содержит названия операций, поэтому остаётся локальным артефактом разрешённой Workspace; не передавать его внешней LLM или другой организации, не записывать исходные данные в журнал. Сохранять через оригинальный механизм артефактов Agent, при больших результатах возвращать проверенную ссылку и digest, а не весь ответ. Зарегистрировать доступную операцию после проверки установленной Node.js и пакета скрипта с зависимостями. Не считать автоматически подключённой к Agent до исполнения через действующий ToolProviderPort, Task/Result и Human Review. Выходной код 0 означает успешную локальную группировку, 2 - HOLD; ни один код не разрешает экспорт.
