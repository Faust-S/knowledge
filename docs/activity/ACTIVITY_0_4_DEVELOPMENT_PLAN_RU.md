# IWXA Activity 0.4. План и первая реализация

База: release/0.3, bccd0fad3a1c97270b242ccb4c5e7ce7ec4183f3, установленная квалификация 45197570949. Релизную ветку не изменять.

## Целевой маршрут

Домен -> разрешённые факты и модели -> восстановление внешним инструментом -> Activity: группировка, проверка смысла и применимости, обезличивание -> оригинальный IWXA Exchange -> адаптация и фактический Result получателя. Agent координирует подключённые инструменты. Atlas планирует конкретные Work. Не создавать ещё один графовый движок, Task Engine, IAM, Store, Core, Router, редактор BPMN, симулятор или формат .iwxa.

## Последовательность

- A4.1: локальное сравнение исходных моделей D05 и затем штатный доменный readback. Модели и исполнения не смешивать. В первой итерации использовать только существующий operation-route; схема данных определяется доменом.
- A4.2: приём результатов Rust4PM/Propel через действующие Agent ToolProviderPort и артефакты Workspace. Полная траектория/варианты, объектные связи, эпистемические статусы. Не использовать анонимные алиасы разных выборок как общую семантику.
- A4.3: переносимая технология с областью применимости, существенными требованиями, входами, выходами, ролями, критериями приёмки, различиями вариантов и ссылками на доказательства в исходной среде. Подтверждение предметным владельцем; стандартные BPMN/DMN через оригинальные инструменты Agent.
- A4.4: квалифицировать ARX для табличных обобщений, Presidio для текстов, OpenDP для допустимой агрегированной статистики. Проверить риск связывания графа и повторных публикаций. Измерять полезность обобщения и проверять полномочия отдельно.
- A4.5: принимать воспроизводимые результаты Mesa/SimPy/SIMOD/Prosimos из Agent, сохранять происхождение и модельный статус. Не считать модель исполнением.
- A4.6: использовать оригинальный Exchange T2/T3 для подтверждённого предметного профиля технологии. Не вводить новый формат или экспорт на основании одного UI-флага.
- A4.7: независимый импорт, адаптация получателем, планирование через Atlas при необходимости, исполнение доменом.
- A4.8: оценка фактической полезности (качество, затраты, длительность, повторное применение) с сопоставимыми базой и результатом.

## A4.1-I. Локальная группировка нормативных моделей

Семантика маршрутов сверена с разрешённым источником D05 (без публикации приватных исходников). Программа принимает существующий объект калькулятора operation-route или локальную копию его исходного Kernel Result. Это не доказательство полномочий, подписи, актуальной Workspace или физического исполнения.

Раздел «Группировка маршрутов» в «Реконструкция»: до 24 отдельных JSON-файлов общим объёмом до 8 МБ; 128 операций, 1024 зависимости на маршрут. Встроенные модели для первого запуска обозначены примером. Все вычисления происходят локально в существующем Activity; сырые записи не сохраняются. При смене раздела выборка очищается.

Группировка: точное название/тип, признак параллельности, контрольная веха, полный набор прямых зависимостей. Смена исходных ID и порядок записей не меняют группу; повторяющиеся смысловые пары требуют ручного сопоставления. Один ID маршрута не может увеличивать число моделей через разные редакции. Длительность, ресурсы, материалы, примечания и параметры маршрута сравниваются отдельно; индивидуальные значения не копируются в результат. Отсутствующие параметры явно отмечаются. Названия операций остаются в частной локальной карточке, поэтому внешняя передача запрещена.

Количество моделей не является числом независимых хозяйственных исполнений; равенство структуры не устанавливает эквивалентность технологии или пригодность к повторному использованию. A4.1-I не изменяет оригинальный D2, A2, T3 grants или IWXA Exchange.

Критерий текущего шага: тесты независимости ID, разных названий и связей, повторных редакций, циклов, конфликта форматов, несовпадений параметров, отсутствия экспорта; TypeScript, исходная квалификация на Windows/Linux, установленное Tauri и старые маршруты. Дальше: квалификация чтения настоящих сохранённых моделей D05 через разрешённый источник и сопряжение с Agent.

## A4.1-II. Точка вызова для параллельной разработки Agent

Опциональная локальная точка входа: tools/activity-d05-route-review.mjs. Не является отдельным приложением, механизмом обмена или программным владельцем Workspace. При наличии квалифицированной Node.js среды адаптер оригинального ToolProviderPort может вызвать Node с этим точным скриптом без shell, передав через stdin JSON-массив уже разрешённых существующих моделей operation-route (до 8 МБ). Аргументы пути/команды не принимаются. stdout содержит единственный JSON локального результата либо типизированный HOLD с кодом, без исходных ошибок/путей. Процесс не читает Kernel, сеть и файлы.

Результат совпадает с вычислением нативного интерфейса. Он содержит названия операций, поэтому остаётся локальным артефактом разрешённой Workspace; не передавать его внешней LLM или другой организации, не записывать исходные данные в журнал. Сохранять через оригинальный механизм артефактов Agent, при больших результатах возвращать проверенную ссылку и digest, а не весь ответ. Зарегистрировать доступную операцию после проверки установленной Node.js и пакета скрипта с зависимостями. Не считать автоматически подключённой к Agent до исполнения через действующий ToolProviderPort, Task/Result и Human Review. Выходной код 0 означает успешную локальную группировку, 2 - HOLD; ни один код не разрешает экспорт. 


## A4.1-III. Штатное предметное чтение сохранённых моделей

База A4.1-I/II: 4c3d5428b56a1fd5d6e4a3525cbf2a00dc6adda8, квалификация 45374965308, 5/5 PASS. Стабильная release/0.3 остаётся на bccd0fad3a1c97270b242ccb4c5e7ce7ec4183f3.

Реализация d05-route-host.mjs использует существующий createSubjectKernelBinding из оригинального T3 (проверенный pin fd927a1efb083219442d9504285f75fa738dbdda). Внутри доверенного Host выбираются только активные Result ru.5ibs.productionops.operation-route версии 1.0.0 из текущей Workspace. Для getWorkspace/listObjects/getObject применяется штатный подписанный доступ activity.read / activity.analysis; Activity не выдаёт право и не вызывает сырой Kernel в обход D1. Запрос списка использует существующие schema_id, include_deleted и limit. Поддерживается до 24 моделей и 8 МБ; при большем объёме результат HOLD, а не скрытое усечение. Список и детали проверяются по исходному содержимому и повторному чтению, смена контекста или отзыв права прекращают чтение. Это не атомарный снимок БД.

Группировка использует прежний reviewD05RouteModels. Итог содержит только локальное представление с именами операций, типами и зависимостями, без исходных ID, Workspace, прав, полного payload. Названия остаются частными сведениями. ORIGINAL_SIGNED_SELECTED_READBACK подтверждает способ получения сохранённой модели, а не независимое физическое исполнение, эквивалентность технологии, анонимность или право передачи. export_allowed=false.

### Подключение в действующем Host (поручение для D05/Agent)

Доверенный продуктовый Host, который уже владеет исходной T2-сессией и оригинальным подписанным Control, передаёт enableD05RouteReview:true в существующую функцию openActivityFromOriginalT2Host. При наличии собственного подписанного invalidation stream передаётся существующий subscribeExistingInvalidation. Функция возвращает прежний port и отдельный необязательный d05RouteHost, состоящий ровно из readSelectedRoutes и subscribeInvalidation. Не создавать второй SSE, подписанта, Store, IAM или механизм выбора Workspace. Параметр по умолчанию false. Он только включает предметную возможность, не создаёт grant.

При монтировании существующей поверхности mountActivityHostSurface передать t3Host: opened.port и d05RouteHost: opened.d05RouteHost. Экран «Группировка маршрутов» показывает действие «Получить сохранённые маршруты» только при успешной подписке на источник. Если такой Host не предоставлен, по-прежнему работают локальные файлы. При отзыве или изменении контекста текущая выборка удаляется, поздний асинхронный ответ не восстанавливает её. Не подключать этот локальный результат к внешней модели ИИ без отдельного разрешения.

Оригинальный универсальный D2 read сохраняет прежний контракт и не выдаёт реальные названия из собственной событийной проекции.

## A4.2-I. Просмотр результата Rust4PM

Существующий Agent `runtime/r4pm_program.py` (ветка process-modeling, 3b431260f3709ba0ed46d35556d124c39f9f37ab) формирует JSON `engine/version/operation/data` для `count_ocel`, `discover_dfg`, `discover_ocdfg`. Activity 0.4 принимает этот точный локальный результат в разделе «Результаты Process Mining», сохраняет частоты и отдельные графы типов объектов, повторно использует graph-order только для представления топологии. DFG не содержит полные траектории и не доказывает причинность или независимое исполнение. Вхождения общих событий в разных объектных графах не суммируются как уникальные события. Локальная копия не доказывает оригинальный Agent Task/Result, права, анонимность или передачу. Публикация закрыта. Новый Job публичного CI использует настоящий pinned r4pm==0.6.2 и самостоятельно формирует открытые модельные XES/OCEL, без приватных checkout. Дальше: связать подтверждённый артефакт исходного Task через существующий ToolProviderPort, квалифицировать полный результат с траекториями и исходными версиями. Не считать эту интеграцию установленной до соответствующего прогона.

## A4.1-IV. Группировка с учётом заявленных требований качества

В дополнение к сравнению route graph реализован отдельный слой сравнения действующих source Result D05: operation-route, quality-plan, quality-check-template. Это исходные типы 1.0.0, а не новый формат обмена или второй конструктор технологий. План связывается с маршрутом и шаблонами только по совпадению собственных предметных ссылок и исходных отношений Kernel based_on. Привязка к операции проверяется по её ID в собственном маршруте и общему сопоставлению операций группы. Сравниваются поля критериев/допусков, метода и выборки, ролей/свидетельств, действий/блокировки, примечаний и предметного контекста. Нет автоматической конвертации единиц, доказательства качества, нормативной приёмки или вывода об эквивалентности технологии. Отсутствующая/конкурирующая карта, неподтверждённая связь и незаполненный существенный критерий дают неполную сопоставимость. Исходные значения критериев и частные ID в выходном отчёте не воспроизводятся.

Для автономного Activity и прежней точки вызова tools/activity-d05-route-review.mjs поддержаны либо прежние route records, либо до 24 локальных JSON исходного вида ObjectWithRelations (один Result на файл: object, relations.incoming, relations.outgoing). Новая смешанная выборка не подтверждает источник и не открывает Exchange. Для доверенного Host в исходной openActivityFromOriginalT2Host при enableD05RouteReview:true предусмотрен отдельный параметр includeD05QualityPlans:true (по умолчанию false). Чтение карт/шаблонов выполняется в той же выбранной Workspace посредством оригинальной подписанной subject binding, с ограничением числа записей и совокупного объёма, повторным чтением списка и связей. При недоступности этой возможности прежняя группировка маршрутов сохраняется. Renderer port не расширен.
