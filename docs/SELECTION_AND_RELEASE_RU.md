# Отбор и квалификация реально работающих агентов IWXA — 0.1

## 0. Что является объектом библиотеки

**Агент-исполнитель** — существующая реально запускаемая агентная программа либо проверенная конфигурация существующего agent runtime, которая может получить задачу, использовать допустимые инструменты, самостоятельно провести рабочие шаги и вернуть проверяемый результат. **Не считаются агентами**: один промпт, Skill, модель LLM, task list, классификатор профессий, vector DB, общий агентный фреймворк без готовой реализации, копия чужого README или демонстрационная оболочка.

Объект: ОДИН агент → его подлинный upstream → конкретная версия → среда/зависимости → заявленные возможности → испытанные возможности → ограничения → воспроизводимые квитанции → подключение через **существующий** Personal Agent. Не заводить вторые TaskTypes, Core, Store, Skill registry, AgentRuntimePort, ToolRuntime.

## 1. Этапы поиска и сортировки (НЕ утверждают готовность)

**S0 DISCOVERED:** официальный исходный repo/релиз, реальный код, идентичность разработчика, тип агента; ничего не запускали. Источник не должен быть фальшивой копией или просто подборкой ссылок.

**S1 SOURCE_SCREENED:** зафиксировать exact commit/tag, README/лицензию на том же commit, лицензионные и аппаратные условия, способ локального запуска, угрозы (сеть/секреты/файлы/команды), значимые зависимости. Мошенническое происхождение, недоступный код, неопределённые права или запрещённые способы использования — REJECT/HOLD. Для кандидатов в данном репозитории подтверждены только источник и файлы README/LICENSE, **не полный аудит безопасности**.

**Приоритет отбора**, не оценка качества: реальная пользовательская функция + доступный локальный Windows маршрут + несовпадающий с уже покрытыми полезный функционал + приемлемая лицензия + совместимость с моделью и инструментами + проверяемые права/изоляция. Нет универсального рейтинга по звёздам GitHub, популярности, количеству «навыков», бенчмарку разработчика или рекламе.

## 2. Проверка реального исполнения

**S2 INSTALL_TESTED:** установить в *изолированный тестовый профиль* из точного пинованного источника, записать версии, hash исполняемых файлов, OS, сеть, зависимости, выбранный AI provider/model. Проверить запуск/закрытие/рестарт. Никаких персональных данных; случайно установленная программа не получает полномочий IWXA.

**S3 TASK_TESTED:** подобрать >=3 независимых предметных задачи для объявленного класса, сделать хотя бы два запуска каждого варианта и >=3 отрицательных сценария: пропущенные данные, запрет на внешнее действие/сеть/файл, недоверенная инструкция во входных данных; по риску — отмена/неизвестный результат/повтор. Для каждого запуска сохранять верифицированные входы, целевой результат, фактический результат/дифф, ошибки, затраты/время, нарушения и воспроизводимость. Критический отказ по правам или приватности → немедленный HOLD, даже если большинство примеров прошло. Проверять по внешним критериям, а не оценке самого агента.

Неизменяемые исходные задачи и тесты не равны продемонстрированному выполнению; синтетический тест валидатора не свидетельствует об успешной работе агента. Для сравнения по возможности использовать тот же провайдер+инструменты в обычной схеме Personal Agent, чтобы понять, в чём улучшение.

**S4 IWXA_VERIFIED:** требуется настоящий запуск именно через действующий `PA.PRODUCT.PORT.AGENT_RUNTIME@0.14.0`, разрешённые ToolRuntime/capabilities и доступность для выбранного класса PRIVATE/PUBLIC только если это доказано. Получить Task→результат→Human Review→сохранение/readback→закрытие→повторное открытие без повторной отправки действия. Утраченный ответ и опасное действие не повторять вслепую. Пакет получает статус «проверен» **для конкретной версии, набора capabilities, среды, приватности и класса задач**. Нельзя расширить статус на другие задачи/платформы/модели/версии без испытаний.

## 3. Принципы приёмки

Hard gates: подтверждённый upstream, разрешённое использование, настоящее agent behavior, контролируемый runtime, известные внешние воздействия, отказ без критических нарушений, наблюдаемые результаты, recovery, exact evidence binding. Нет хотя бы одного — **НЕ VERIFIED**.

Содержательное решение: готовое средство лучше или хотя бы надёжнее/воспроизводимее обычной модели с теми же инструментами **в заявленном сценарии**; иначе целесообразность его распространения не подтверждена. Если специализированный исполнитель работает только с одним окружением, сертификат действует только там.

Переходы статуса не делаются разработчиком только по описанию или CI валидатора. Класс `SOURCE_SCREENED` означает проверенные публичные сведения об источнике и лицензии, **не** успешную инсталляцию, не безопасность, не агентную функцию и не интеграцию.

## 4. Практический порядок поиска

Начать с уже связанного с Personal Agent Goose; далее Aider как специализированный инструмент изменения кода; OpenHands и Cline сравнить с предыдущими по необходимости. Предпочитать реальные agent applications и их официальные источники; Frameworks/skills/collections без запуска не включать в agent library. Проводить по одному исполнителю до S4, затем брать следующего. Не создавать десятки недопроверенных карточек ради большого каталога.

## 5. Публикация

PUBLIC репозиторий: только разрешённые метаданные, pinned source, код аудита, **синтетические** задачи/fixture и обезличенные test receipts; не хранить здесь пользовательские PRIVATE, секреты или копии приватных продуктов. PRIVATE: исследования, подробные оценки, решения, закрытые источники и рабочие протоколы. В любом случае пакет исполнителя не должен содержать скрытых прав на запуск, изменение файлов или сеть.

Внешние независимые ИИ могут в будущем рецензировать готовый candidate, но в текущем цикле разработчик доводит и самопроверяет данные. Нельзя подменять реальные запуски несколькими текстовыми обзорами.
