# IWXA Workspace & Workflow: самостоятельная линия развития

**Решение владельца 26.11.2026:** развивать общую Workspace и Workflow как крупное самостоятельное функциональное направление IWXA. Не привязывать общую технологию к Advice Logistics, отдельному домену или интеграции конкретной программы. Это развитие действующего T3/Agent, не новый продукт, ядро, Store, Host, Graph, Task Engine, IAM, Router или формат обмена.

## 1. Исходная основа и владельцы

- Выпущенная T3 0.3.0: release/t3-0.3.0@fd927a1efb083219442d9504285f75fa738dbdda. Рабочая ветка work/2026-11-26-workspace-workflow-development начинается непосредственно от этой базы. Номер будущего выпуска общей технологии пока не назначен. Текущие T3 release, T4, Agent 0.6.5, stable/0.6.4, Center и Publisher не менять из этой линии.
- Канонический общий Workspace/Host/View State и модульные contributions остаются в packages/t3-core. Оригинальный Kernel/Store/Exchange сохраняется. Agent остаётся владельцем своего исполнения Task, Graph, ToolRuntime, DurableAutomation, Human Review и Result; предметные программы и домены остаются владельцами своих моделей, операций и данных. Не копировать Agent Graph в T3 для получения универсальной визуальной доски.
- Personal Agent 0.6.6 остаётся отдельной продуктовой работой после фиксации 0.6.5. Самостоятельную разработку общих механизмов владелец разрешил сейчас; интеграцию в Agent выполнить от принятой базы, не подменяя текущую квалификацию.
- Corporate: только одна полная исходная подписанная Workspace компании, все данные работы сохраняются в ней, export/import всей Workspace с history/assets/relations/schemas. Личный/предметный обмен и междоменные проекции не заменяют этот контур. D1 authority и D7 entitlement проверяются оригинальными владельцами. Лицензия, доступный viewer, выбранный объект и граф не дают права выполнять действия.
- Объект деятельности, представление, методика, исполнительная Task и предметная модель различны. Свободное исследование допустимо без исполняемого Graph, Atlas, домена, установленной программы или обязательного шаблона. Визуальный порядок материалов не создаёт исполнительные зависимости.

## 2. Разработанные участки

### W01: стабильная идентичность и жизненный цикл сохранённых представлений

[eeaa952b](https://github.com/Faust-S/knowledge/commit/eeaa952b3d358f1e63fd5d3210749d00b9c48a2b). Развит original workspace-persisted-view-state, RichWorkspaceReadModel и workspace.view-state.save. Старые IDs сохраняются. Новый ID 128-bit random (WebCrypto), не вычисляется из названия. Unique normalized name сохраняет прежнее поведение обновления; неоднозначность требует явного выбора. Кнопка «Изменить» открывает исходный вид и фиксирует его baseRevision; переименование не меняет ID. Новое создание после удаления получает новую идентичность. Неизвестный outcome создания в текущей сессии использует тот же ID и сверяет видимый readback, не повторяет запись при совпадении. Старый 32-bit helper оставлен для совместимости, не применяется для создания в основном Rich Workspace. Не обещать глобальную уникальность названий при нескольких конкурентных клиентах; явное редактирование разрешает неоднозначность без молчаливого overwrite. Original owner CAS и существующая проверка полномочий не заменены.

### W02: сохраняемый состав материалов и режим профессионального вида

[66150d0b](https://github.com/Faust-S/knowledge/commit/66150d0b4345f77a54dfa8759ad9922873ca3010). Existing internal saved-view v1 дополнен optional presentation: version=1, mode, ordered selected refs (object_id + revision), detail ref. Это additive field существующего View State, не новый schema family, Asset, Store или формат .iwxa. Старые filter-only records не требуют миграции и сохраняют исходную форму. Сохранение локального вида и persistent view используют тот же capture. Scope/current revision сверяется по полученному текущим Host каталогу; нет копий payload, разрешений, скрытых действий или автоматической замены старой редакции. При обновлении объектов после открытия представления вычисляется новый read-only restore. Изменившиеся/недоступные материалы не попадают в выбранную композицию; виден счётчик, пользователь может принять доступный состав. Новый save не скрывает неполный состав. Сравнение сейчас штатное сравнение метаданных двух объектов, не готовый универсальный научный viewer. Лимит 256 относится только к этому сохранённому выбору; отказ явный, без усечения исходной Workspace.

**Совместимость:** новая реализация читает прежний v1. Старый клиент способен проигнорировать новый optional presentation и при обновлении прежнего объекта потерять его; downgrade-writing не квалифицирован и не должен объявляться безопасным. До выпуска проверить точную схему original Host/Kernel и штатный .iwxa, сохранение extended records при обмене с предыдущими поддерживаемыми редакциями, явную обработку неизвестных представлений, lifecycle и совместимость миграции. Не повышать статус до принятого продукта на основании допустимости поля в source validator.

## 4. Дальнейшие функциональные этапы

| Этап | Содержательный результат | Граница |
| --- | --- | --- |
| W03 | Универсальная композиция нескольких существующих viewers: связанные панели, порядок, размеры, выбор, отображение исходных материалов и результатов | Развит original View State/registries, не копировать данные и не делать технический граф обязательным |

| W05 | Типизированная передача результата, зависимость от точных входов, проверяемое повторное использование и выборочный пересчёт | Original Result/Task/Graph owners, действующие разрешения и единицы; нативный execution gate |
| W06 | Альтернативы, версии, сравнение, подтверждение решения и продолжение после остановки | Прежние результаты неизменны, сохранённый checkpoint не является новым grant |

| W08 | Переиспользование в Agent и всех доменах по их actual capabilities/profiles, настоящие U1-U3 и A-C | Независимая квалификация каждой принятой версии, права и лицензии не расширяются |

Первый следующий полезный участок: закончить W01/W02 на настоящем original Host с одним групповым прогоном, устранить подтверждённые дефекты; затем W03 через existing Viewer/Panel contributions. Не тратить последующие циклы только на новые планы и тестовые substitute. При разработке W04/W05 прочитать актуальный Agent Graph и T3 project-process contracts; границы owners не менять автоматически. После фиксации 0.6.5 связать принятую Workspace capability с 0.6.6, проверить U1/U2 и собственные исследования пользователя. Не делать квалификацию одной программы обязательной для автономной работы всех остальных.
