# Exchange: повторный импорт и границы квалификации, 27.11.2026

## Дефект и исправление

В общем Exchange T2/T3 число вновь записанных объектов и событий сравнивалось с полным составом архива. Уже присутствующие идентичные записи ошибочно считались отсутствующими. Это отдельный дефект представления квитанции, а не новый дефект Kernel. При существующей цели учитываются оригинальные `objects_skipped` только при отсутствии явно пропущенных конфликтов. Счётчик вставленных событий не равен объёму сохранённой истории; оригинальная атомарная транзакция отвечает за отказ при несовпадении Event. Свежая рабочая область сохраняет строгие проверки состава. Сохранены проверки неполных данных, настоящих конфликтов и корпоративный readback. В выборочном режиме учитывается выбранный состав. Квитанция не выдаётся за независимое чтение.

- T2: [63d61f87](https://github.com/Faust-S/T2/commit/63d61f872ad88694096abbf748855546b0a4ec21).
- T3: [63d76beb](https://github.com/Faust-S/knowledge/commit/63d76beb11752b6e3f3c545d79f30b14b0bd816b).

## Проверка

[Публичный одноразовый CI 46010486598](https://github.com/Faust-S/knowledge/actions/runs/46010486598), оба job SUCCESS: T2 106/106, T3 112/112, TypeScript и сборка каждого PASS, существующий корпоративный readback T3 PASS. В оригинальном T2 Host с двумя независимыми нативными DB8 и неизменённым узким паспортом на принятом Kernel (Runtime e1737245...) и кандидате (559e8dd7...) прошли первый импорт, повтор того же .iwxa, нулевые новые объекты/события при повторе, сохранение объектов/связей/истории/переносимого содержимого вложений, холодный перезапуск, read-only запрет и настоящий конфликт skip без перезаписи изменённой записи. Не проверялась установленная Windows-пара Agent/Admin этим прогоном.

## Применимость

D01–D11 получают исправление через принятый общий Host соответствующего уровня при очередном адресном обновлении, не через предметный форк. D12 не требует его для обычного публичного сайта. Предметные алгоритмы и формат .iwxa не изменены. Agent/Admin используют отдельный подписанный профиль только в корпоративном режиме. Publisher (лицензии/age), Atlas (проектные Results и получатель), Activity (разрешённая проекция/технология) проверяются только по фактически используемому пути; не объявлять их неисправными по общему UI. Workspace & Workflow получает наследуемое исправление через тот же One Core.

Исключения предпросмотра при обратной передаче через узкий паспорт, наблюдавшиеся в 46008892603, не являются основанием расширять права или останавливать обычный доменный импорт. Сценарий A→B→A между независимыми корпоративными получателями с полными подписанными полномочиями и установленными продуктами остаётся отдельной незавершённой квалификацией кандидата Event; не переносить этот HOLD на независимые функции всех доменов. Изменение порядка сериализации Event подтверждено прежними регрессиями, отдельный Kernel artifact не объявлен принятым этим UI-исправлением.

**Решение:** EXCHANGE_RECEIPT_FIX_ENGINEERING_PASS; исходные рабочие ветки для интеграции, main/stable/артефакты и продуктовые пины неизменны. Дальнейшее обновление только через общий выпуск, один потребитель за раз. Закрытые Actions не запускались. Никакого расширения полномочий, второго Kernel/Store/Exchange.
