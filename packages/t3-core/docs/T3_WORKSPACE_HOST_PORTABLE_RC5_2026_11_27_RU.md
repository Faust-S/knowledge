## Применение

Доменный разработчик получает точный архив и receipt по release tag, проверяет SHA-256,
использует прежние команды t3:platform:verify / t3:platform:import / t3:host:prepare
(или существующие эквиваленты), сохраняет предметную логику и идентичность сервиса.
Никакого нового интегратора или онлайн-зависимости сайта от репозитория T3.
Прежние platform inputs и стабильный сайт сохраняются до собственной приёмки.
Для доменного помощника согласовать его отдельный original assistant pin и domain skills;
не использовать публичный generic ZIP как готовый домен. Обычный T2/персональный
Exchange не требует корпоративного Agent/Admin маршрута.

## Независимая попытка Codex и исправление запуска

Предоставленный владельцем отчёт: точная идентичность Windows HTTPS ZIP PASS, A–F BLOCKED до открытия Host. Отсутствует Cert: в первой оболочке; при запуске в PowerShell 5.1 сертификат создан, но CurrentUser Root trust не подтверждён; сервер не слушал 18443. Сертификат удалён. Для устранения зависимости от Windows certificate store готовится отдельно именованный локальный комплект http://localhost:18443. Оригинальная схема Domain Shell 2.0 допускает http://localhost:<port>, оригинальный Host проверяет точный origin, Service Worker имеет предусмотренный localhost fixture route. Временная копия оригинального materializer допускает только этот точный дополнительный origin при сборке локального стенда; тот же алгоритм инвентаря, исходные compiled assets, BLI и Kernel неизменны. START.cmd вызывает bundled Node напрямую; сервер строго на 127.0.0.1 и Host localhost:18443. Не меняются системное доверие, браузерные флаги и требования HTTPS развернутых продуктов. До отдельной успешной доставки и реального доступа встроенного браузера статус Codex BLOCKED.

Адресная квалификация локального запуска без сертификата: [46034089610](https://github.com/Faust-S/knowledge/actions/runs/46034089610), статус при записи IN_PROGRESS.
