## Применение

Доменный разработчик получает точный архив и receipt по release tag, проверяет SHA-256,
использует прежние команды t3:platform:verify / t3:platform:import / t3:host:prepare
(или существующие эквиваленты), сохраняет предметную логику и идентичность сервиса.
Никакого нового интегратора или онлайн-зависимости сайта от репозитория T3.
Прежние platform inputs и стабильный сайт сохраняются до собственной приёмки.
Для доменного помощника согласовать его отдельный original assistant pin и domain skills;
не использовать публичный generic ZIP как готовый домен. Обычный T2/персональный
Exchange не требует корпоративного Agent/Admin маршрута.

## Передача независимому проверяющему

Для устранения прежнего блокера незапущенного Host применяется существующая доставка rc.2 с пинами rc.5. Локальный комплект формируется из опубликованного архива, не компилируется и не включает модель, закрытый код, TLS-ключ или второй Kernel. Запуск на Windows с явным согласием на временный localhost TLS certificate. Тот же dist можно материализовать для заранее предоставленного корневого HTTPS origin с помощью scripts/prepare-t3-rc5-acceptance.mjs. Удалённый Codex должен иметь действительный доступ к этому origin; локальный адрес сам по себе не обеспечивает удалённый доступ.
