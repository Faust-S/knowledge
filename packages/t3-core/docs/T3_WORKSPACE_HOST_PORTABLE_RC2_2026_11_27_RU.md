заменён проверкой фактического фокуса, первой навигации и отмены устаревшего кадра.

закрытый подписант, пользовательские данные и model weights отсутствуют.

В Learn и аналогичном домене:
1. Создать новую директорию runtime/t3-platform/0.3.1-rc.2, не уничтожать 0.3.1-rc.1.
2. Обновить оригинальную domain platform pin из опубликованного candidate-receipt.json;
   сохранить domainId, serviceId, существующий предметный module inventory,
   оригинальный T2 baseline, проверяемый runtime hash и остальные поля, специфичные для домена.
   sourceTree означает дерево src, sourcePackageGitTree означает дерево packages/t3-core.
   portableArtifactId, если поле требуется существующей схеме, 15190628293.
3. Оригинальный общий помощник остаётся на своей точной исходной редакции; в domain assistant pin
   согласовать sharedEngineSource с новым sourceCommit. Не создавать второй движок.
4. Проверить и импортировать только внутренний platform-inputs.zip. Однократная явная подготовка
   доменного Host использует точный checkout квалифицированного T3 и опубликованный package lock,
   существующие предметные модули домена и оригинальный помощник, затем сохраняет локальный Host.
5. Обычная сборка сайта использует локально закреплённый комплект, не скачивает T3, не клонирует
   другие репозитории и не перекомпилирует платформу. Один конечный dist.
6. Проверить сборку, реальный доменный UI, сохранение, перезапуск, обмен, mobile и согласие
   на T3/модель. До продуктовой приёмки не присваивать PRODUCT_ACCEPTED и не подменять действующий сайт.

В текущем Learn уже существуют npm scripts t3:platform:verify, t3:platform:import,
t3:host:prepare, t3:inputs:retain, build:product:t3, test:learn-t3-assembly.

## Независимая приёмка

Независимый проверяющий работает именно с указанным tag/commit, архивом и SHA.
Не повторяет уже пройденные накопительные тесты как единственную приёмку и не меняет исходники
ради положительной отметки. Проверяет действительный интерфейс через встроенный браузер Codex,
без Playwright/Puppeteer/Chromium automation в Codex. Если требуется физическое устройство,
использует доступное реальное устройство или честно фиксирует аппаратный блокер.
 
Обязательные сценарии: первая загрузка и навигация без ложного "Раздел недоступен";
действительная недоступность/отказ полномочий; явное включение T3; создание Workspace,
предметного результата, истории и файла; перезапуск; экспорт и независимый импорт оригинального
.iwxa; восстановление без сети. Отдельно: реальный физический WebGPU; явное согласие на скачивание
официальной модели; генерация; редактирование, Human review и явное сохранение через Kernel;
полное закрытие приложения/браузера; отключение сети; холодное восстановление Host и модели из кеша,
новый ответ и новое сохранение через Kernel, без скачивания модели. Проверить desktop/mobile
и отсутствие фонового скачивания/второго Store/второго движка. Не имитировать GPU, модель,
сеть, реальные квитанции или OS install. Отчёт: SHA, SHA-256, устройство/ОС/браузер,
реальный адаптер, маршрут, видимые результаты, receipts, PASS/FAIL/BLOCKED, точные причины.
Только после такой приёмки решается готовность соответствующего продукта. Существующий
статус установленной экосистемы T3 этим документом не изменяется.

Норматив: исходники T3/T4 и отдельные домены не откатывались. Закрытые Actions не использованы.
