# K05 / Agent 0.6 — выпускные испытания реальной эффективности

**18.11.2026. Состояние: NOT_ACCEPTED.** Это критерии выпуска, а не отчёт о достигнутой эффективности. K05 остаётся необязательным read-only kit, без собственного Core/Task Engine/Graph/Store/IAM. Основной Agent 0.6, T3, Office, Activity и Atlas остаются владельцами своих исходных данных.

## G0. Штатный установленный путь перед сравнением

1. Один точный установленный Windows Agent SHA; штатный Setup Core/установленный Tauri/реальный `llama.cpp b11827` + GGUF; исходный файл запроса не должен подвергаться escape-преобразованию. Проверяется **побайтовая привязка исходного Core prompt к `llama-cli -o`**, не произвольный stdout.
2. Доказать `Task accepted → actual Model inference → Result imported → Human Review approved → saved Result → cold Core restart → independent Task/Result readback`; каждый этап исходной цепочки и его SHA/receipt сохраняются в закрытом owner Store. Сценарии с `PAUSED/awaiting_result` остаются FAIL, не пропускаются.
3. Нативный UIA штатного базового Result и затем UIA K05; отрицательное сравнение **двух реально принятых, но разных по исходным условиям** Task обязано показать `NOT_COMPARABLE`; K05 не запускает модель повторно и не создаёт новый Result.
4. Только после G0 оценивать G1. Source/TS/CI PASS, синтетические DemoReplay, упаковка и успешный Setup **не заменяют G0**.

## G1. Два действительных разных ИИ-исполнителя, а не разные имена DemoReplay

- Два проверенных локальных model identities (поставщик, GGUF SHA-256, runtime binary SHA, adapter и фактическая квитанция генерации), каждый исполняет исходную Task в одном аппаратном профиле. Для реального K05 различаются сами model/executor identities, не только Task IDs.
- Не менее **трёх повторов каждого исполнителя** по одной зафиксированной задаче, затем воспроизвести на двух других задачах (одна текстовая, одна с документом/источником). Это минимальная квалификационная выборка, **не** доказательство статистической значимости экономического эффекта.
- Отдельные принятые Task IDs, одинаковый objective, источники, права, skill/instruction revisions, критерии приёмки, бюджет, Workspace и зафиксированные входные данные. Все несовпадения исходных условий → `NOT_COMPARABLE`, никогда не автокорректировать.
- Порядок исполнителей чередовать; учитывать cold/warm start отдельно, ограничение CPU/RAM/GPU, время версии, условия компьютера. Prompt/system SHA сохраняются как *диагностика модели*, но не подменяют каноническую Task equivalence.

## G2. Наблюдаемая полезность, а не факт принятия человеком

| Метрика | Подтверждающее свидетельство | Запрет |
| --- | --- | --- |
| Фактическое качество результата | Слепая оценка по заранее установленным критериям корректности, полноты, опоры на исходные данные и пригодности, плюс проверяемые выполненные действия | Human Review `approve` как единственная оценка |
| Время | Модельная latency и сквозное Task→Result время раздельно, с временными метками исходного owner | Смешивать model latency и end-to-end |
| Токены | Только `prompt_tokens/completion_tokens` из реального provider usage и оригинальной записи запуска | Заполнять отсутствующие значения длиной текста или `requested_output_tokens` |
| Стоимость | Оплаченная/зафиксированная ставка и фактическое потребление с валютой и источником; локальная энергия/амортизация только при измерении | Считать `0` вместо `UNKNOWN` |
| Работа человека | Фактические время проверки, исправления, повторные действия, отклонения и достигнутый результат с owner evidence | Считать клик «Принять» выполненной работой или экономией |
| Устойчивость | Повторная генерация, восстановление после перезапуска, доля отказов и состояния `PAUSED/DEAD` | Удалять неуспешные прогоны из знаменателя |

K05 показывает сравнимые наблюдаемые показатели, **только если есть их источник**. Исходное качество может отличаться при одинаковых входах; вывод «какая модель лучше» требует реальной оценки. Корреляция, удобство и экономия не являются причинным эффектом без контролируемого эксперимента.

- Test runner: только разрешённый публичный `Faust-S/Center` Windows с временным read-only доступом к закрытому Agent. Private Actions запрещены. В публичных логах только статусы, коды и технические SHA; без текстов, EXE, приватных source bundles, полных логов, архивов и model output.
- K05 не должен быть обязательной runtime зависимостью Agent/T3; предоставлять отдельный интерфейс и on-demand read-only Core owner запрос. Не вводить новый Task Engine/Store/Graph, не делать Atlas обязательным.
