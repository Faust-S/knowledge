## Задача испытания

Установить на одном замороженном входе, насколько existing native U1 `EVENT_LOG_JSONL` отличает технически недействительный журнал от формально правильных, но содержательно изменённых записей. Исключить ошибочную интерпретацию «U1 принял событие = событие действительно произошло». Сравнить исходный и искусственно изменённый source snapshot; не создавать новый validation engine.

**Реальные записи** взяты из ранее закреплённой копии BPI open problems; **каждое искажение синтетическое**. На уровне сценариев ground truth — только знание автора, какую строку он изменил; это НЕ независимая разметка реальной работы, Task или полезности процесса.

## Механизм

В исходном [BPI13 XES → U1 адаптере](bpi13_xes_u1_replay.py) без изменения логики вынесены две функции: `project_registered_rows` для повторного использования одинакового pseudonymous projection и `inspect_registered_rows` для единственного оригинального U1. Новая [исследовательская проверка](bpi13_mutation_stress.py) берёт ту же детерминированную выборку — **12 cases / 50 зарегистрированных событий** — и по одному создаёт семь контролируемых вариантов. Внутри U1 сохраняется Git blob `eb15aec5ba1a749c29d7c40a868127e1a384b6bf` без исправлений.

Результат каждого варианта фиксируется в агрегированном JSON: приняли ли исходный формат, SHA snapshot поменялся ли, изменились ли число и context units, сколько ссылок в source-bound receipt меняется. **Не экспортируются** исходные case identifiers, actor IDs, названия реальных занятий, строки XES или event JSONL.

## Семь сценариев и наблюдение на настоящем исходном журнале

| Контролируемое изменение | Изменённые байты источника | Что сделал native U1 | Допустимый научный вывод |
|---|---|---|---|
| Удаление одной зарегистрированной записи | Да | Принял формально допустимый log с числом событий −1 | Внутри новой версии журнала событие отсутствует; не доказано, что действие не происходило |
| Добавление искусственного действия | Да | Принял (+1) | Валидный формат и новое событие не доказывают, что новое действие существовало |
| Дата события изменена на −90 суток | Да | Принял | Timestamp в записи проверен по синтаксису, но фактическая дата не доказана |
| Переназначение события другому case | Да | Принял | Case grouping зависит от данных источника; верность принадлежности не подтверждена |
| Изменение названия действия | Да | Принял | Название события — заявленное содержимое источника, не самостоятельная классификация действия |
| Дублирование event_id | Да | **Отклонил** с `DUPLICATE_EVENT_ID` | U1 правильно обнаруживает нарушенную структурную уникальность |
| Предположенное действие, не записанное ни в одном логе | Нет | Принял тот же исходный snapshot без изменений | Утверждение о таком действии остаётся `UNKNOWN`; ни U1, ни какой-либо log-only метод не может вывести его из отсутствия записи |

**Итого:** пять действительно изменённых семантически, но формально допустимых журналов приняты; ещё один вариант вообще не меняет данных и потому неразличим с оригиналом; один технически неверный вариант отклонён. Формула «6 accepted / 1 rejected» описывает **формальную приёмку журналов**, а не «83% достоверной реконструкции», не precision и не качество Task Discovery.

## Интерпретация и архитектурное решение

**U1 исправлять не требуется.** Его явный контракт — неизменяемые источниковые якоря и честная маркировка `REPORTED_EVENT_IN_UNVERIFIED_LOG`, а не экспертиза фактической деятельности. Приём журнала U1 — не признание действительности событий; это подтверждено текущими исходниками и тестом.

**Сопоставление двух версий возможно**, поскольку при наличии исходного snapshot изменяются их SHA и версии receipts. Но SHA сам по себе не говорит, *какое* действие изменено, кто прав и какая версия отражает действительность. Исходные `REV-` evidence IDs связаны с source ID, поэтому нельзя использовать равенство/неравенство REV между разными версиями как содержательное доказательство без надлежащей карты соответствий. Перечисление affected/unchanged events должно опираться на local source rows и доказанное сопоставление внутри разрешённого owner context.

**Отсутствие цифровой записи не является доказательством отсутствия действия.** Никакое «улучшение prompt», LLM или статистика неполной цифровой трассы не снимает проблему идентифицируемости: для дополнительных утверждений требуются независимые сведения (например, разрешённые документы, интервью, наблюдения или новое контролируемое испытание). Такие сведения могут быть ограничены смещениями и не гарантируют полноты.

**Более правильный следующий маршрут:** строить ограниченные *модели зарегистрированных событий*, сохранять сравнение версий, выявлять кандидатов на дополнительную проверку и ставить task hypotheses только там, где есть отдельное основание/цель и принятая граница достоверности. Не расширять T0/T1, U1, engine или персональный runtime из одного этого теста.

## Не выполнено / следующий научный этап

- Сравнение байтов копии GitHub с официальным 4TU source и аудит прав: `PENDING`.
- Реальная independent human gold-разметка частных задач, скрытой работы или исходных мотивов: `NOT_MEASURED`.
- Причинные выводы о действии человека, эффективности организационной системы и полезности новых Tasks: `NOT_ESTABLISHED`.
- Возможные следующие контрпроверки: независимый источник к одному изменённому случаю, two-source corroboration vs copied source; временной дрейф и постфактум регистрация; различие версии логов, статуса процесса и интереса principal; source-first vs catalogue-first Task hypothesis на равных материалах.
- Передача в существующий Task Research Engine и Context Compiler — только через `RawEvent` и отдельные проверенные источники, без автоматического превращения registered event в целевую задачу.

**Итог:** первая адресная проверка **смысловой границы existing U1** на реальном корпоративном журнале с известными искусственными вмешательствами успешно выполнена и показала, почему форматно корректный журнал недостаточен для реконструкции фактической человеческой деятельности. Это эксперимент по границе достоверности, а не оценка качества полноценного Activity Discovery.
