# IWXA TASK-EXP-01 — один локальный цикл экспертизы и измерения затрат

**Статус:** инженерный адаптер проверен на синтетических входах; фактической независимой разметки людей и E5 gold пока нет.

## Назначение

`owner_review_cycle.py` последовательно вызывает **два действующих компонента**, не заменяя их: 

1. Исходный `Faust-S/iwxa/knowledge/task-catalog/engine/research/task_exp_01_review_bridge.py` для проверки двух слепых экспортов Label Studio и сохранения частного списка расхождений.
2. Публичный `review_effort.py` для статистики `annotations.lead_time` и **условной**, а не фактической стоимости труда.

Скрипт использует **ровно те же два файла** разметки в обоих шагах, останавливается при изменении входов и не допускает заявления о gold или adjudication. Измерения относятся к **двум разметкам**, а не к сравнению двух методов помощи человеку. Измеренное Label Studio `lead_time` не доказывает реальное активное время: оно может включать паузы.

## Выполнение в разрешённой локальной среде

Предпосылки: действующий исходный checkout `Faust-S/iwxa` (нужна проверенная версия bridge), публичный checkout `Faust-S/knowledge`, созданный owner-local `e5-source-first.json`, два **действительно заполненных** независимыми людьми и экспортированных `review-a.json` / `review-b.json`. Ранее применённые адаптеры `labelstudio_project_setup.py` и оригинальный owner `task_exp_01_labelstudio_import.py` остаются без изменений.

**Единый путь от генератора до Bridge:** в [M3_REVIEW_EXPORT_HANDOFF_RU.md](M3_REVIEW_EXPORT_HANDOFF_RU.md) исходный `task_exp_01_real_slice.py --restricted-output` сохраняет `/PRIVATE/e5-envelope.json`. В `--source-first-packet` передавайте **этот же фактически созданный файл** (либо иной реально указанный путь `--restricted-output`), а не новое имя. `--restricted-import-output /PRIVATE/labelstudio-import.json` — отдельный файл импорта Label Studio; не путайте его с пакетом для owner Bridge.

Из корня публичного `knowledge`:

```sh
python research/task-discovery/owner_review_cycle.py \
  --owner-root /PRIVATE/iwxa \
  --source-first-packet /PRIVATE/e5-envelope.json \
  --review-a /PRIVATE/review-a.json \
  --review-b /PRIVATE/review-b.json \
  --restricted-disagreements-out /PRIVATE/disagreements.json \
  --effort-out /PRIVATE/review-effort.json \
  --hourly-rate-usd 50 \
  --confirm-independent-local-review
```

`--hourly-rate-usd` необязателен. Ставка — допущение, не фактический расход. Данные разметки, непубличные разногласия и результаты измерения оставлять в разрешённом owner-local контуре; не загружать на GitHub или в публичный Actions. Если исходный bridge меняется, адаптер сообщает HOLD до явной переквалификации новой версии.

## Целостность результатов и повторный запуск

`owner_review_cycle.py` теперь проводит два действующих шага в **закрытых временных каталогах рядом с конечными файлами**. Полученные `disagreements.json` и `review-effort.json` проходят проверку схем, 8 исходников, 16 аннотаций, неизменности входных SHA и отсутствия `human_gold`. Лишь затем оба файла публикуются под конечными именами без разрешения перезаписи. Режимы отказа:

- Сбой owner bridge либо второго `review_effort.py`: временные файлы удаляются, два конечных файла не создаются; повторный запуск допустим с прежними входами.
- Конфликт выходного имени перед публикацией: возврат `HOLD`; чужой существующий файл не заменяется, опубликованного частичного результата нет.
- На POSIX оба результата создаются с правами `0600`. Требуется возможность создавать hard link в **том же файловом разделе**; при её отсутствии возврат `HOLD`, без обхода защиты.

Дополнительная защита от конкурентной замены: при сбое второго `hard link` откат первого результата выполняется **только когда устройство и inode совпадают** с временным файлом, опубликованным этим запуском. Если другой процесс успел удалить или заменить первый результат, чужой файл сохраняется. Адресные тесты теперь воспроизводят отказ именно второго link и конкурентную замену первого; проверка на коммите `4073c76b0e2e88757d7135090f82dd5e839828c0` — [Actions 41862801222](https://github.com/Faust-S/knowledge/actions/runs/41862801222) (**SUCCESS — проверено по GitHub Actions 04.11.2026**). Это защищает откат, но не обеспечивает двухфайловый атомарный commit для стороннего наблюдателя.

Две записи в файловую систему не являются общей атомарной транзакцией: процессы, одновременно читающие выходные имена, должны запускаться **после успешного завершения команды**, а не наблюдать файлы в процессе публикации. Это инженерная целостность owner-local handoff, **не** доказательство независимости людей, gold или adjudication.

Проверено публичной source-first регрессией: [run 41858272318](https://github.com/Faust-S/knowledge/actions/runs/41858272318) — SUCCESS (85 tests). Исходный owner review bridge не изменялся.

## Контроль специализированной формы перед owner Review Bridge

Перед запуском исходного `task_exp_01_review_bridge.py` локальный цикл теперь проверяет **точную owner XML** по пути `knowledge/task-catalog/engine/research/TASK_EXP_01_LABEL_STUDIO_SOURCE_FIRST.xml` внутри `--owner-root`. Используется уже существующий `review_form_contract.check_xml`, закреплённый Git blob `7922b634b145bc064a33f95d04c058d3c5da18f6`; проверяются выбор `INDEPENDENT_TASK`, три поля интерпретации, `review_coverage` и источник `source_text`. Файл только читается в owner-local checkout, в публичную ветку не переносится.

Отсутствие или изменение формы, а также попытка подмены общим E5 XML дают `HOLD` **до запуска Bridge и до создания выходных файлов**. Проверка служит подтверждением инструментального контракта, а не доказательством, что люди действительно работали по этой форме; факт сохранённого XML в каждом Label Studio отдельно проверяется `labelstudio_project_setup.py`. Предшествующее обязательство frozen U1/regex `93e76fc6983364c5718a8e26f797d7220ed51899cd90bf92f15731d3c5f94bf0` не изменено.

## Что тестируется, чего ещё нет

- Адресные offline-тесты проверяют два последовательных вызова, подтверждение источников, неизменность входных файлов, наличие реального локального пакета разногласий и совпадение его числа случаев с квитанцией owner bridge, отказ при ошибках bridge и отсутствие ложного результата при частичной записи. Модуль не создаёт второй Task Engine, Store, Rights или систему аннотаций.
- Настоящий владелец TASK-EXP-01 должен выполнить маршрут с двумя реальными людьми. До этого **M3 HUMAN REVIEW / ADJUDICATION = PENDING**; precision, recall, F1, реальное активное время и экономия относительно непосредственного чтения — **NOT MEASURED**.
- После разрешения экспертных разногласий потребуется **отдельное** сравнение frozen U1/regex и независимого gold, а также парное испытание реальной трудоёмкости методов. Прямое чтение источника остаётся сильной простой альтернативой.
