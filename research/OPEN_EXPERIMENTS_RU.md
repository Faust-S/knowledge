# IWXA — открытые исследования смежного маршрута

Дата 03.11.2026. Первый этап миграции переносит границы, публичную методику и полностью синтетический fixture; приватные исходники не опубликованы.

**Task Discovery/U1:** существующий owner — `Faust-S/iwxa`. Сравнивать явно заданную пользователем Task с обнаруженными Task Candidates; подтверждать исходную цитату, лицензию, неоднозначность и независимую оценку. TaskType ≠ Task человека; отвергнутые объекты не использовать как эталон.

**Cross-Lab:** публичный независимый эксперимент должен сравнивать простой поиск с более сложным подбором контекста на одинаковых разрешённых данных: точность/лишние источники, время, качество конечного Result. Старые R1–R4/Context Compiler — research/reference у владельца, не продуктовая интеграция. Не строить вторую память.

**Agent Platforms:** отдельное направление сравнений действительных open-source программ/исполнительных сред, не строка каталога специализированных агентных workflow. Для точных версий проверять OSI-лицензию, коммерческое распространение, Windows binaries/NOTICE, local/offline, model/tool/Skills interfaces, реальную пригодность. Выбор и запуск остаются в Personal Agent.

**Первый открытый Result reference:** `fixtures/meeting-task-result.json` + `tests/test_open_task_result_boundary.py` используют уже имеющийся валидатор `tools/verify_meeting_followup.py` (из QA-ветки). Это авторские синтетические данные и структурный тест буквальной опоры. Не запущена модель; не создана/принята корпоративная Task; не выполнен внешний эффект; `ADAPTED_NOT_EXECUTED` и `IWXA_VERIFIED=0` сохраняются.

Следующий критерий пользы — собственно PA Task→Model/Skill→Graph→Result→Human Review→restart на единой исходной ревизии. Только после него оценивать расширенный selection и администрирование результатов.
