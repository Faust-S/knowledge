## 2. Задача, ради которой создаётся продукт

Пользователь запускает **Bypass Manager** и отдельно установленную **Amnezia Premium**. Программа должна самостоятельно проверять сеть, определять используемый VPN-протокол, систематически исследовать разрешённые DPI-профили, измерять реальную стабильность и выводить конкретное следующее действие, если его невозможно выполнить программно. Цель — **действительно работающий интернет для браузеров и других Windows-приложений, с устойчивым видео**, а не просто зелёный статус подключения или успешный CI.

Поддерживаемые в сторонней Amnezia два варианта: **AmneziaWG** и **VLESS**. VLESS по наблюдениям владельца часто сразу отключается, поэтому начинать с AmneziaWG, но не игнорировать альтернативу при предметной диагностике. Нет подтверждённого официального API полного управления Amnezia Premium; **не вытаскивать ключи, не угадывать endpoint, не генерировать случайные IP**. Если требуется ручное отключение/включение/смена протокола, показывать точную инструкцию **в самом интерфейсе**, затем автоматически обнаруживать изменение состояния.

Публичный репозиторий не должен содержать: реальные IP и адреса VPN-узлов пользователя, имена Wi-Fi, MAC, данные провайдера, геометки пользователя, имена процессов, приватные пути и VPN-ключи. В **локальном интерфейсе** внешний IP и приблизительная геолокация показываются пользователю по его запросу; **общий экспорт** должен оставаться обезличенным. Не возрождать старое название, встречавшееся в исторических прототипах.

## 3. Состав текущего приложения

- `manager.go`, `gui_windows.go`: Windows GUI и маршруты запуска.
- `guide_windows.go`, `guide_plan.go`, `guide_quality.go`, `guide_transfer.go`: последовательный мастер AmneziaWG/VLESS, подбор, измерения, подробный `latest-guide.json`.
- `process_window_windows.go`, `runtime/Scripts/Start-Profile.ps1`: собственный `winws2`/WinDivert с оригинальными Lua, ограниченными временными испытаниями и учётом владения процессом. **Не переписывать zapret2**.
- `network_health*.go`, `runtime/Scripts/Get-NetworkHealth.ps1`: пассивная диагностика адаптеров, MTU, ошибок и маршрутов.
- `live_*.go`: локальное отображение согласованного внешнего IP, примерной географии и замер скорости.
- `path_probe*.go`: задержки/ICMP/DF без преувеличения достоверности.
- `stability*.go`: 15-минутное наблюдение в сопровождении настоящего видео, без ложного утверждения о наблюдении браузерного буфера.
- `app_routes*.go`, `runtime/Scripts/Get-AppSockets.ps1`: снимок TCP-соединений и UDP-сокетов по процессам. **Это не подтверждение публичного IP каждого приложения**.
- `mtu_trial*.go`, `runtime/Scripts/Temporary-MTU.ps1`: добровольная временная проба ActiveStore IPv4 MTU с независимым watchdog и возвратом исходного значения; MTU нельзя применять постоянно без доказанного отката.
- `support_bundle.go`, `tuning_plan.go`: сводный обезличенный `latest-support.json`, предложения сравнительных проверок.
- `Tests/`: проверки реальной PowerShell 5.1 на Windows CI, но **без VPN**, сетевого перехвата и изменения сетевых настроек CI-машины.

## 4. Исправления этого прохода

1. Ранее диагностировалось «физическое TCP-соединение приложения», даже если это было **ожидаемое соединение самого VPN-клиента с его внешним сервером**. Теперь снимок отдельно содержит `non_vpn_physical_bound`, `vpn_client_physical_bound`, `physical_classification_complete`, а предупреждение для обычных приложений формируется только при подтверждённом разделении чисел. Классификация VPN-клиента по имени процесса остаётся эвристикой, **не доказательством безопасного выхода**.
2. Скрипт MTU восстановлен после ошибочного запуска независимого сторожа: если Windows ещё не пыталась изменить MTU, не оставлять заблокированный `private-mtu-trial.json` без работающего watchdog.
3. Добавлен `Tests/Test-MTU-Rollback-Mock.ps1`, имитирующий Windows-сетевые командлеты и проверяющий Start→Restore, конкурентную правку MTU и отказ запустить сторожевой процесс. Он **не меняет сеть Windows CI**.
4. Новые Go-тесты отделяют штатный физический трафик VPN-клиента от возможных обходов VPN со стороны других программ; экспорт не содержит имён процессов.

## 6. Что ещё осталось сделать (приоритет)

**P0 — независимая фактическая проверка пути отдельных Windows-программ:** тип локального TCP-сокета и маршрут ОС не подтверждают публичный IP выбранного приложения. Разрабатывать способ получать результат *из контекста приложения*, с разрешения пользователя, без массового перехвата и записи приватных адресов в публичный отчёт. Учитывать UDP/QUIC отдельно. Браузер со своим прокси/расширением может иметь иной выход, чем приложения ОС.

**P0 — надёжный полевой цикл подключения:** адаптер и `0.0.0.0/0` или пара `/1`, фактический выход, счётчики, полные загрузки, повторные подключения, сравнение двух протоколов и релевантных DPI-профилей. Если конечный внешний адрес и порт Amnezia неизвестны, **пропускать DPI**, а не подставлять случайные значения.

**P1 — реальное восстановление MTU:** проверить реальный Start/Restore/watchdog/аварийный выход на отдельном допустимом Windows-тестовом узле. Сначала восстановить, затем менять. Не менять DNS, маршруты, брандмауэр, Kill Switch или драйверы без отдельного проверяемого отката.

**P1 — измерения приложения и видео:** повторный замер внешнего IP, скорости, DNS/TCP/TLS/TTFB, ошибок соединений, потерь и джиттера, продолжительное видео и объяснимый итог; отсутствие ответа на ICMP не приравнивать к потере связи.

**P2 — UX:** один главный маршрут «Диагностировать → подобрать → подключить → проверить приложения и видео → мониторить». Одна конкретная инструкция человеку только когда программа не может исполнить действие в официальном Amnezia. Технические поля и разные отчёты вторичны. Сводный экспорт с временной последовательностью и точными кодами отказов.

## 9. Реальная диагностика Windows 16.11.2026: мастер не завершил последовательность

Обезличенный пользовательский latest-support.json показал: AmneziaWG/NONE видел маршрут и движение адаптера, но HTTPS на первом CDN дал PARTIAL_TRANSFER 160675/2097152 байт за 20 с; второй CDN завершился NETWORK_ERROR_REDACTED. Исходный прямой IPv4 не был подтверждён перед тестом, поэтому VPN egress и IP-изменение не доказаны. AmneziaWG/UDP-FAKE и UDP-REPEAT пропущены из-за NO_MATCHING_VERIFIED_ENDPOINT. VLESS/NONE не поднял VPN-маршрут. На VLESS/TLS-SPLIT после просьбы отключить VPN пользователь не получил завершённого результата. SPEED_NOT_VERIFIED: разовая загрузка 2 МиБ прошла, крупные тесты HTTP_403/NETWORK_ERROR_REDACTED; это не 0 Мбит/с.

Исправлены две причины отсутствия понятного завершения:
- Отказ от модального подтверждения внутри мастера: действия теперь запрашиваются прямо в основном окне, с кнопками «Готово»/«Нет / пропустить», работающей «Остановить» и тайм-аутом 3 минуты. Также без модального окна запрашивается согласие на загрузку семи оригинальных компонентов winws2.
- Финальный отчёт после отмены, отказа или тайм-аута получает CompletedUTC и терминальный код GUIDE_INCOMPLETE/CANCELLED; незавершённый вариант закрывается INCONCLUSIVE/CANCELLED. Существующие измерения сохраняются, отсутствующий VPN handshake не выдаётся за факт.

**Полевой статус:** REAL_NETWORK_NOT_ACCEPTED. Для очередного испытания сначала проверять автономную работу VPN и базовый исходный IPv4 на самом ПК, затем мастер. Не переносить пользовательские IP/порты/конфигурацию в GitHub. Для полевого отчёта достаточно latest-support.json после завершённого прохода.

Дополнительная инженерная правка по полевому зависанию: PowerShell wrapper теперь устанавливает Go exec.Cmd.WaitDelay = 3 секунды для закрытия каналов вывода после аварийного завершения PowerShell или запущенного им процесса. Это устраняет класс неограниченного ожидания CombinedOutput при наследовании stdout/stderr и дополняет штатный 40-секундный лимит реального старта winws2. Исполнение и выход из ограниченного этапа фиксируются в журнале. Реальный Windows-полевой возврат и живой VPN остаются не проверены.

## 10. Автоматическое обнаружение внешнего транспорта 16.11.2026

Пользователь Amnezia Premium может не видеть IP и порт VPN-сервера. Никаких стабильных IP для всех клиентов нет: параметры Premium могут обновляться через официальную API-конфигурацию.

Get-OuterEndpoint.ps1 пассивно ищет две согласованные записи из доверенного XRay-процесса AmneziaVPN (VLESS: TCP Established/SynSent) или текущего WFP Security Event 5156, если стандартный Windows-аудит уже был включён (AmneziaWG: UDP). Каждый кандидат подтверждается как публичный IPv4/порт с физическим исходящим маршрутом. События старше 90 секунд, несколько разных адресов, неподтверждённый процесс или маршрут отклоняются. Сведения о сервере держатся только в памяти процесса; в JSON и настройки не записываются. Нативный handshake этим НЕ подтверждён.

Нельзя получить удалённый UDP peer из обычного Get-NetUDPEndpoint. Если аудита Windows 5156 нет, программа не включает его тайно, не читает VPN-профили/подписки/ключи и не выдаёт адрес по догадке. При этом обычная диагностика без DPI работает. Пользователь больше не обязан искать адрес в интерфейсе Amnezia.

Дополнение: официальный отдельный Windows-клиент AmneziaWG может включать awg.exe. Менеджер теперь пассивно вызывает его диагностику текущего внешнего peer, **только при совпадении имени интерфейса с активным VPN-адаптером**, проверяет публичный IPv4/порт и физический маршрут. Публичные peer identifiers из ответа CLI отбрасываются немедленно, никакие приватные ключи и конфигурации не читаются. Если CLI отсутствует или использует другое имя туннеля, используется WFP fallback, иначе код UNAVAILABLE. Нативная проверка handshake остаётся отдельной задачей.

## 11. Исправление реального дефекта HTTP timing

При независимом анализе исходников обнаружен дефект Go defer: функции downloadFrom и guideRangeDownload присваивали Timings в отложенном вызове, но возвращали копию неназванной переменной результата раньше выполнения defer. Поэтому DNS/TCP/TLS/TTFB всегда могли оставаться нулевыми, включая HTTP 200 и HTTP 403. Возвраты изменены на именованные (named result); добавлены нативные Go-регрессии HTTP 200, HTTP 403, усечённого HTTP 206 и некорректного URL. Нулевые DNS/TCP/TLS после исправления иногда допустимы (cache/reuse/слишком малое время), но реальный задержанный TTFB теперь обязан сохраняться.

## 12. Сервер VPN может поменяться после переподключения

Для автоматического endpoint-наблюдения добавлена повторная проверка после подключения Amnezia. Перед получением статуса HTTPS менеджер заново сопоставляет фактический внешний IP, порт, протокол и физический маршрут с теми, на которые уже настроен собственный WinDivert-фильтр. При изменении, неоднозначности или недоступности повторной проверки итог варианта становится `OUTER_ENDPOINT_CHANGED_OR_UNVERIFIED`, менеджер останавливает только принадлежащий ему DPI-процесс и не объявляет соединение рабочим. Это существенно для автоматически сменяемых Premium-серверов. На VLESS/AWG без подтверждения нет автоматического угадывания адреса; native VPN handshake также остаётся не подтверждённым.


## Главный экран: что изменилось 17.11.2026

Главная операция: **«Проверить и улучшить»** (пошаговый мастер со стандартными результатами). Отдельно доступна **«Измерить скорость»**; все остальные функции находятся в **«Подробности»**, а ввод серверных IP, транспортов и продвинутый запуск DPI помещён в подраздел **«Ручные параметры»**. При работе мастера «Остановить» всегда видно и можно открыть журнал, не прерывая диагностику. Кнопка для собственного DPI названа «Выключить собственный DPI», а не «Восстановить сеть»; Amnezia и системные маршруты она не сбрасывает.

Главный экран теперь разделяет **DPI сейчас**, **DPI применялся в последнем испытании** и **эффект DPI**. Признак \`OWN_DPI_STARTED\` в журнале означает только реальный запуск собственного фильтра, подготовка Lua не считается запуском. Сравнение до/после допускается лишь при одном протоколе, одинаковых HTTPS-источниках и размерах, по крайней мере двух полных загрузках, подтверждённом сравнении исходного выхода и трафике VPN-адаптера на обоих этапах. Даже тогда результат только \`POSSIBLE_IMPROVEMENT\`, \`POSSIBLE_REGRESSION\` или \`NO_CLEAR_GAIN\`, а не подтверждённое качество YouTube/браузера. Когда мастером испытан только \`NONE\`, он явно пишет **«DPI не применялся; эффект не измерен»**.

Скорость показывается с отметкой возраста измерения. Уже через 15 минут она помечается как устаревшая, а не текущая. \`latest-support.json\` вычисляет отдельный \`dpi_effect\`, помечает старые источники как \`STALE_INCLUDED\` и сводку без новых данных как \`HISTORICAL_ONLY\`. Диагностические данные в обезличенном JSON сохраняются; IP, география и параметры Amnezia туда не добавляются.

**Граница:** это UI/interpretation upgrade, не доказательство успешного обхода DPI или настоящего VPN-handshake на ПК пользователя. \`REAL_NETWORK_NOT_ACCEPTED\`.

## Упрощение выбора уже используемого протокола (17.11.2026)

После нажатия **«Проверить и улучшить»** Bypass Manager показывает прямо в основном окне две кнопки: **AmneziaWG** и **VLESS**. Выбирается тот протокол, который уже включён в отдельной Amnezia Premium. Никакие ключи, подписки или конфигурации не читаются, поэтому выбор фиксируется как пользовательский, а не как подтверждённый через API.

Для VLESS первым испытанием теперь будет **VLESS / NONE** и затем только VLESS-совместимые DPI-стратегии; ошибочный принудительный переход сначала на AmneziaWG больше не нужен. Для AmneziaWG сохраняется существующий контролируемый маршрут с возможностью позже запросить ручное переключение на VLESS. Неизвестный протокол не принимается.

Внешние HTTPS-сервисы увидят публичный IP тестируемого соединения. Это указано непосредственно при выборе протокола. Пока пользователь не выбрал протокол, сеть не измеряется и DPI не запускается. Кнопка **«Остановить»** работает в процессе выбора, в том числе когда Amnezia не отвечает. Отмена создаёт конечный отчёт с кодом \`NO_PROTOCOL_SELECTED\` и не подменяет его успешным результатом.

Нативный Win32 smoke проверяет появление обоих вариантов, доступность «Остановить» и исчезновение ожидания после отмены. Полевой VPN-handshake и фактическую работу видео этот тест не доказывает.

## Возраст публичного IP и сброс старого результата при изменении маршрута (17.11.2026)

Внешний IPv4 и приблизительный регион относятся к HTTPS-пробе **на момент её выполнения**, а не к постоянному состоянию компьютера. Теперь локальные строки показывают возраст этого измерения. Когда прошло 15 минут или после новой проверки Windows выявилось отличие состояния полного VPN-маршрута от состояния во время замера, старые IP/регион перестают отображаться как текущие; пользователю предлагается повторить «Измерить скорость». При недоступной диагностике VPN-маршрута программа не заявляет изменение на основании отсутствующих данных. Изменение IP у сторонних программ и браузера не доказано только пробой Bypass Manager.

## 17.11.2026: исправление реального перекрытия Win32

Независимая визуальная проверка кадров Windows CI (1040×744) выявила, что журнал перекрывает третью строку диагностических кнопок в «Подробностях». Причина: прежний расчёт `h-90` мог поднимать журнал выше размещения последней строки. На низком дисплее сетка кнопок уплотняется, журнал начинается после всех кнопок; при недостаточной высоте журнал скрывается вместо перекрытия действий. Проверка нативных `GetWindowRect` в Windows smoke теперь отказывает при пересечении кнопок и журнала. Нет заявлений о реальном VPN handshake или об эффективности DPI без фактического сравнения.


## 17.11.2026: Local Proxy и трёхэтапная проверка A/B/A

В обычном мастере VLESS без TUN, когда Amnezia продолжает работать, больше не приравнивается к прямому выходу. Если установленный процесс Amnezia открыл локальный прокси на `127.0.0.1`, Bypass Manager может автоматически проверить его SOCKS5/HTTP CONNECT через независимые HTTPS-сервисы, без чтения конфигураций или ключей. Официальный Amnezia Premium Local Proxy - отдельный режим: системный VPN и локальный прокси одновременно работать не могут. Локальный порт при включениях меняется. При неудаче проверки программа не считает обычный прямой интернет успешным VPN.

«Программы / соединения» теперь различают локальное подключение выбранной программы к порту прокси Amnezia и обычный VPN-адаптер. Это только сетевой признак; публичный IP **каждого** приложения не доказан. Имена процессов остаются на компьютере, экспорт содержит лишь обезличенные счётчики.

Для DPI-опыта мастер теперь выключает собственный `winws2` и проверяет третий этап A/B/A. Проверяются две полные загрузки от того же CDN того же размера, состояние VPN-маршрута, адаптерного потока и публичного IPv4. Коды результата: `ABA_POSSIBLE_SPEED_REVERSAL`, `ABA_POSSIBLE_AVAILABILITY_REVERSAL`, `ABA_NOT_REPRODUCED`, `ABA_INCONCLUSIVE`. Даже воспроизводимая корреляция не доказывает причинность DPI. Исходный IPv4 не считается прямым, если Amnezia запущена без TUN.
