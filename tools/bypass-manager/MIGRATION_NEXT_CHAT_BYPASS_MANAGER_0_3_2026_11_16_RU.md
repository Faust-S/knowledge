## 2. Задача, ради которой создаётся продукт

Пользователь запускает **Bypass Manager** и отдельно установленную **Amnezia Premium**. Программа должна самостоятельно проверять сеть, определять используемый VPN-протокол, систематически исследовать разрешённые DPI-профили, измерять реальную стабильность и выводить конкретное следующее действие, если его невозможно выполнить программно. Цель — **действительно работающий интернет для браузеров и других Windows-приложений, с устойчивым видео**, а не просто зелёный статус подключения или успешный CI.

Поддерживаемые в сторонней Amnezia два варианта: **AmneziaWG** и **VLESS**. VLESS по наблюдениям владельца часто сразу отключается, поэтому начинать с AmneziaWG, но не игнорировать альтернативу при предметной диагностике. Нет подтверждённого официального API полного управления Amnezia Premium; **не вытаскивать ключи, не угадывать endpoint, не генерировать случайные IP**. Если требуется ручное отключение/включение/смена протокола, показывать точную инструкцию **в самом интерфейсе**, затем автоматически обнаруживать изменение состояния.

Публичный репозиторий не должен содержать: реальные IP и адреса VPN-узлов пользователя, имена Wi-Fi, MAC, данные провайдера, геометки пользователя, имена процессов, приватные пути и VPN-ключи. В **локальном интерфейсе** внешний IP и приблизительная геолокация показываются пользователю по его запросу; **общий экспорт** должен оставаться обезличенным. Не возрождать старое название, встречавшееся в исторических прототипах.

## 3. Состав текущего приложения

- `manager.go`, `gui_windows.go`: Windows GUI и маршруты запуска.
- `guide_windows.go`, `guide_plan.go`, `guide_quality.go`, `guide_transfer.go`: последовательный мастер AmneziaWG/VLESS, подбор, измерения, подробный `latest-guide.json`.
- `process_window_windows.go`, `runtime/Scripts/Start-Profile.ps1`: собственный `winws2`/WinDivert с оригинальными Lua, ограниченными временными испытаниями и учётом владения процессом. **Не переписывать zapret2**.
- `network_health*.go`, `runtime/Scripts/Get-NetworkHealth.ps1`: пассивная диагностика адаптеров, MTU, ошибок и маршрутов.
- `live_*.go`: локальное отображение согласованного внешнего IP, примерной географии и замер скорости.
- `path_probe*.go`: задержки/ICMP/DF без преувеличения достоверности.
- `stability*.go`: 15-минутное наблюдение в сопровождении настоящего видео, без ложного утверждения о наблюдении браузерного буфера.
- `app_routes*.go`, `runtime/Scripts/Get-AppSockets.ps1`: снимок TCP-соединений и UDP-сокетов по процессам. **Это не подтверждение публичного IP каждого приложения**.
- `mtu_trial*.go`, `runtime/Scripts/Temporary-MTU.ps1`: добровольная временная проба ActiveStore IPv4 MTU с независимым watchdog и возвратом исходного значения; MTU нельзя применять постоянно без доказанного отката.
- `support_bundle.go`, `tuning_plan.go`: сводный обезличенный `latest-support.json`, предложения сравнительных проверок.
- `Tests/`: проверки реальной PowerShell 5.1 на Windows CI, но **без VPN**, сетевого перехвата и изменения сетевых настроек CI-машины.

## 4. Исправления этого прохода

1. Ранее диагностировалось «физическое TCP-соединение приложения», даже если это было **ожидаемое соединение самого VPN-клиента с его внешним сервером**. Теперь снимок отдельно содержит `non_vpn_physical_bound`, `vpn_client_physical_bound`, `physical_classification_complete`, а предупреждение для обычных приложений формируется только при подтверждённом разделении чисел. Классификация VPN-клиента по имени процесса остаётся эвристикой, **не доказательством безопасного выхода**.
2. Скрипт MTU восстановлен после ошибочного запуска независимого сторожа: если Windows ещё не пыталась изменить MTU, не оставлять заблокированный `private-mtu-trial.json` без работающего watchdog.
3. Добавлен `Tests/Test-MTU-Rollback-Mock.ps1`, имитирующий Windows-сетевые командлеты и проверяющий Start→Restore, конкурентную правку MTU и отказ запустить сторожевой процесс. Он **не меняет сеть Windows CI**.
4. Новые Go-тесты отделяют штатный физический трафик VPN-клиента от возможных обходов VPN со стороны других программ; экспорт не содержит имён процессов.

## 5. Проверки и критерии готовности

В Linux выполнить из `tools/bypass-manager/`:

```sh
go test -count=1 ./...
go test -race -count=1 ./...
go vet ./...
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags='-H windowsgui -s -w' -o Bypass-Manager.exe .
```

Проверить публичный Windows CI того же HEAD. Для нового PowerShell теста важно проверить реальную работу скрипта, **не только его парсинг**. На Windows CI разрешена нативная квалификация в публичном репозитории. **Не запускать Actions в закрытых репозиториях.** Codex использовать только для недоступных операций и независимой финальной приёмки.

Разделять статусы:

- `SOURCE_TEST_PASS`: Go, статические тесты и Windows-сборка.
- `WINDOWS_CI_PASS`: Win32 GUI, PowerShell, Lua/WinDivert dry-run без интерсепта.
- `REAL_NETWORK_NOT_ACCEPTED`: нет доказательства обхода ограничений на фактическом ПК пользователя.
- `PRODUCT_ACCEPTED` — **не присваивать** без реального продолжительного рабочего VPN, публичного IP, выхода выбранных приложений, скорости и 15-минутного воспроизведения.

## 6. Что ещё осталось сделать (приоритет)

**P0 — независимая фактическая проверка пути отдельных Windows-программ:** тип локального TCP-сокета и маршрут ОС не подтверждают публичный IP выбранного приложения. Разрабатывать способ получать результат *из контекста приложения*, с разрешения пользователя, без массового перехвата и записи приватных адресов в публичный отчёт. Учитывать UDP/QUIC отдельно. Браузер со своим прокси/расширением может иметь иной выход, чем приложения ОС.

**P0 — надёжный полевой цикл подключения:** адаптер и `0.0.0.0/0` или пара `/1`, фактический выход, счётчики, полные загрузки, повторные подключения, сравнение двух протоколов и релевантных DPI-профилей. Если конечный внешний адрес и порт Amnezia неизвестны, **пропускать DPI**, а не подставлять случайные значения.

**P1 — реальное восстановление MTU:** проверить реальный Start/Restore/watchdog/аварийный выход на отдельном допустимом Windows-тестовом узле. Сначала восстановить, затем менять. Не менять DNS, маршруты, брандмауэр, Kill Switch или драйверы без отдельного проверяемого отката.

**P1 — измерения приложения и видео:** повторный замер внешнего IP, скорости, DNS/TCP/TLS/TTFB, ошибок соединений, потерь и джиттера, продолжительное видео и объяснимый итог; отсутствие ответа на ICMP не приравнивать к потере связи.

**P2 — UX:** один главный маршрут «Диагностировать → подобрать → подключить → проверить приложения и видео → мониторить». Одна конкретная инструкция человеку только когда программа не может исполнить действие в официальном Amnezia. Технические поля и разные отчёты вторичны. Сводный экспорт с временной последовательностью и точными кодами отказов.

## 7. Данные для следующего полевого испытания

Из `%LOCALAPPDATA%\BypassManager\results\` разрешено просить **только проверенный обезличенный** `latest-support.json`, при необходимости `latest-guide.json`, `latest-apps.json` и `latest-mtu-trial.json`. В `latest-support.json` объединяются валидированные диагностические отчёты; данные могут быть устаревшими или отсутствовать. **Не просить** `settings.json`, файлы `active/`, приватные VPN-профили, подписки и ключи.

В интерфейсе пользователь может увидеть реальный публичный IP, страну, регион и скорость. Сам **факт смены IP программы не гарантирует**, что браузер, мессенджер, игровой клиент и другое ПО выходят тем же путём.

## 9. Реальная диагностика Windows 16.11.2026: мастер не завершил последовательность

Обезличенный пользовательский latest-support.json показал: AmneziaWG/NONE видел маршрут и движение адаптера, но HTTPS на первом CDN дал PARTIAL_TRANSFER 160675/2097152 байт за 20 с; второй CDN завершился NETWORK_ERROR_REDACTED. Исходный прямой IPv4 не был подтверждён перед тестом, поэтому VPN egress и IP-изменение не доказаны. AmneziaWG/UDP-FAKE и UDP-REPEAT пропущены из-за NO_MATCHING_VERIFIED_ENDPOINT. VLESS/NONE не поднял VPN-маршрут. На VLESS/TLS-SPLIT после просьбы отключить VPN пользователь не получил завершённого результата. SPEED_NOT_VERIFIED: разовая загрузка 2 МиБ прошла, крупные тесты HTTP_403/NETWORK_ERROR_REDACTED; это не 0 Мбит/с.

Исправлены две причины отсутствия понятного завершения:
- Отказ от модального подтверждения внутри мастера: действия теперь запрашиваются прямо в основном окне, с кнопками «Готово»/«Нет / пропустить», работающей «Остановить» и тайм-аутом 3 минуты. Также без модального окна запрашивается согласие на загрузку семи оригинальных компонентов winws2.
- Финальный отчёт после отмены, отказа или тайм-аута получает CompletedUTC и терминальный код GUIDE_INCOMPLETE/CANCELLED; незавершённый вариант закрывается INCONCLUSIVE/CANCELLED. Существующие измерения сохраняются, отсутствующий VPN handshake не выдаётся за факт.

**Полевой статус:** REAL_NETWORK_NOT_ACCEPTED. Для очередного испытания сначала проверять автономную работу VPN и базовый исходный IPv4 на самом ПК, затем мастер. Не переносить пользовательские IP/порты/конфигурацию в GitHub. Для полевого отчёта достаточно latest-support.json после завершённого прохода.

Дополнительная инженерная правка по полевому зависанию: PowerShell wrapper теперь устанавливает Go exec.Cmd.WaitDelay = 3 секунды для закрытия каналов вывода после аварийного завершения PowerShell или запущенного им процесса. Это устраняет класс неограниченного ожидания CombinedOutput при наследовании stdout/stderr и дополняет штатный 40-секундный лимит реального старта winws2. Исполнение и выход из ограниченного этапа фиксируются в журнале. Реальный Windows-полевой возврат и живой VPN остаются не проверены.
