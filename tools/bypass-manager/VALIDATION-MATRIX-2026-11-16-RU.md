# Bypass Manager 0.3 Alpha: матрица отказов и границы приёмки

**Дата:** 16.11.2026. **База:** рабочая ветка `work/2026-11-15-bypass-manager-0-3-alpha`. **Статус продукта:** `REAL_NETWORK_NOT_ACCEPTED`. Это живой отчёт к исходникам, а не утверждение о полностью доказанном VPN.

## Почему полевая попытка не смогла подобрать DPI

В первоначальном пользовательском `latest-support.json`:
- AmneziaWG / NONE: VPN-маршрут и счётчики адаптера были видны, но 2 МиБ HTTPS оборвались на 160675 байтах после ~20 секунд. Второй CDN не ответил. Ни нативный handshake, ни смена IP относительно отключённого VPN не подтверждены.
- AmneziaWG / UDP-FAKE и UDP-REPEAT пропущены: `NO_MATCHING_VERIFIED_ENDPOINT`, потому что версия требовала IP/порт сервера, отсутствующие в интерфейсе Amnezia Premium.
- VLESS / NONE: `VPN_ROUTE_NOT_READY`. VLESS / TLS-SPLIT не завершился из-за блокирующего подтверждения/ограничений последовательного режима.
- Отдельный короткий замер 2 МиБ показывал ~66,9 Мбит/с, но следующие попытки получили HTTP 403 и network error. Правильно: `SPEED_NOT_VERIFIED`, а не «скорость 0».
- DNS/TCP/TLS/TTFB были нулевыми также из-за исправленного дефекта неназванного возвращаемого значения в `downloadFrom` и `guideRangeDownload` (измерение терялось при `defer`).

## Как теперь определять внешний узел без ручного IP

1. Использовать **только фактическую текущую сессию**, не статический список IP Amnezia Premium.
2. AmneziaWG: при наличии `awg.exe` в известных каталогах установленного клиента получить `show all endpoints`, отбросить идентификаторы peer, сопоставить имя текущего адаптера, подтвердить внешний IPv4/порт и маршрут физического интерфейса. Если CLI отсутствует, возможны уже существующие события Windows WFP (Security Event 5156, UDP), только от подтверждённого процесса установленного Amnezia, а не из чужого приложения. Аудит Windows автоматически не включать.
3. VLESS: два последовательных снимка внешних TCP-соединений доверенного процесса XRay из каталога AmneziaVPN, либо уже доступные WFP-события, при однозначных IP/порту и физическом маршруте.
4. `Get-NetUDPEndpoint` **не возвращает удалённую сторону UDP**. Нельзя на его основе «вычислить» сервер. `Get-NetTCPConnection` не доказывает handshake или подлинность сервера, даже при совпадении сокета.
5. Найденный IP/порт — только приватное значение в памяти. Никогда не экспортировать в `latest-support.json`, `latest-guide.json`, публичный лог CI или настройки. Не читать ключи, подписки, конфигурации, командные строки Amnezia.
6. Если Windows не дала достоверные данные, отключить **только соответствующий DPI-опыт**, показать код причины; обычную проверку текущего VPN выполнить. Подмена IP из DNS, подсети, IP-проверки выхода или произвольного списка запрещена.
7. При переключении протокола и после переподключения **проверять текущий peer заново**. Если IP, порт, транспорт или физический маршрут изменился — остановить принадлежащий менеджеру фильтр, зафиксировать `OUTER_ENDPOINT_CHANGED_OR_UNVERIFIED`, а не засчитывать успешный DPI.

## Как запускается CI

Основной workflow: `.github/workflows/bypass-manager-windows.yml` — Windows Server 2022, Go, native GUI, PowerShell 5.1, сеть в read-only, оригинальный winws2 dry-run/Lua, сборка EXE.

Расширенный: `.github/workflows/bypass-manager-scenarios.yml` — Linux Go с `-race`, `go vet`, 25 повторов адресных тестов, Windows cross-build; параллельно Windows 2022 и 2025 с запуском PowerShell моков и GUI smoke. Source snapshot зафиксирован как artifact соответствующего CI.

Ни один публичный GitHub runner не подключается к приватной подписке Amnezia пользователя, не принимает её ключи, не изменяет боевую сеть и не может доказать обход блокировок именно у пользователя.

## Обязательная полевая приёмка до PRODUCT_ACCEPTED

1. На Windows ПК владельца: отдельная Amnezia Premium; проверить обнаружение AWG/VLESS независимо от DPI, без ручного IP.
2. С отключённой Amnezia измерить согласованный исходный публичный IPv4; затем включить каждый протокол и сравнить фактический выход, с явным признаком обновления сервера после reconnect.
3. Настоящее воспроизведение видео >=15 минут, задержки, сбои, скорости при падении пропускной способности; сравнение браузера и выбранных системных программ, включая UDP/QUIC.
4. Если понадобится реальное изменение MTU/DNS/маршрута: сначала независимый сторож, затем проба и проверенный откат, включая аварийное закрытие. Не менять систему ради тестового PASS.
5. Экспорт только обезличенного `latest-support.json`. Не отправлять личные IP, VPN-профили, ключи, адреса серверов.

**Вывод:** гарантировать обнаружение закрытого Premium-сервера на любом Windows без доступа Amnezia к диагностическому API нельзя. Текущая реализация использует только реальные доступные наблюдения, корректно отказывает при невозможности подтвердить узел и не делает из read-only/моков ложный результат подключения.
