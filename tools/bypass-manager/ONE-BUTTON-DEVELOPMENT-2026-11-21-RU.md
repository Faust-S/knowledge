# Bypass Manager 0.4 Alpha: первый нативный режим без VPN

**21.11.2026.** Рабочая ветка: `work/2026-11-20-bypass-manager-one-button`.

## Что реально реализовано

- Новый компактный **Win32-экран с тремя действиями**: **Включить / Выключить**, **Скорость и регион**, **Отчёт**. Старый мастер выбора AmneziaWG/VLESS и ручные параметры больше не являются главным пользовательским интерфейсом.
- Нажатие **Включить** запускает работу существующего оригинального `winws2`/WinDivert без VPN, без внешнего IP сервера, без изменения системных DNS, прокси или маршрутов. При отсутствии бинарных компонентов программа скачивает **семь файлов одного закреплённого upstream-коммита**, сверяет Git blob SHA-1 и отказывается работать с неподтверждённым движком.
- Перед реальным запуском оригинальный движок дважды проверяет аргументы (режимы `--dry-run`, `--intercept=0`). Применяется TLS-стратегия `multisplit` и **автообнаружение проблемных доменов через `--hostlist-auto`** с порогом в три отказа. Внешние домены не задаются IP-адресом VPN-сервера. Настройки браузеров и сам VPN не затрагиваются.
- После запуска проверяется, существует ли **именно свой процесс** (PID, полный путь, время старта). Один и тот же механизм принадлежности использован для выключения. При отмене первой операции выполняется попытка остановить свой процесс и перечитывается его фактическое состояние.
- Нативное окно можно закрыть: запущенный `winws2` остаётся, если пользователь не нажал **Выключить**. При следующем запуске интерфейс проверяет настоящий процесс, а не только файл состояния. Автозагрузка с Windows пока не реализована.
- **Скорость и регион**: по нажатию выполняется собственный HTTPS-тест приложения и согласование внешнего IPv4, примерной географии. Данные IP/географии показываются локально, а в общий отчёт попадают только обезличенные статусы/измерения. **Не подтверждает** IP браузера с VPN-расширением и IP других программ.
- **Отчёт**: `latest-support.json` включает обезличенный `latest-direct.json` со статусом, причиной и признаком `effect_verified=false`, пока нет доказательства изменения доступности конкретного ресурса. Файл автообнаруженных доменов и нативные логи движка не экспортируются.

## Почему режим ограничен пока только TLS/TCP

На первом шаге намеренно не запускаются случайные UDP-стратегии, не перехватываются VPN-handshake и не включается глобальное перенаправление всех протоколов. Выбрана минимальная обработка TCP/443, первый пакет TLS и контрольные пакеты, необходимые для регистрации серии отказов. После квалификации можно добавлять HTTP/80 и QUIC/UDP/443 с раздельным контролем конфликтов и подтверждением конкретных приложений.

## Важное разграничение

- **Локальная адаптация DPI** не создаёт VPN и не шифрует сверх уже действующего HTTPS. Она не меняет видимый IP и не восстанавливает полностью недоступный удалённый IP или лежащий VPN-сервер.
- **Браузерный VPN** в дальнейшей разработке рассматривается как **отдельное установленное расширение или встроенное в браузер приложение**, а не как интерфейс Bypass Manager. Его прокси-путь можно измерить только в самом браузере или через поддерживаемый API, нельзя переносить результат на Windows-программы.
- **Подключение независимых удалённых узлов** при необходимости — следующий этап, не включён в этот коммит.
- Запуск движка и автоматический hostlist **не являются доказательством**, что конкретный заблокированный сайт стал доступен. Варианты блокировки по IP или протоколам вне TLS/TCP могут остаться без решения. Реальная приёмка требует полевого испытания на целевой Windows-сети и пользовательских сайтах/приложениях.

## Проверки

1. `go test -count=1 ./...`, `go test -race -count=1 ./...`, `go vet ./...`, нативная сборка Windows x64.
2. Windows PowerShell 5.1: строгий синтаксический разбор всех скриптов. Оригинальный `winws2.exe` должен принять именно новый `Start-Direct.ps1 -DryRun`, включая Windows-фильтр и `--hostlist-auto`, без загрузки драйвера и изменения сетевого подключения.
3. Windows GUI: ровно три действия, отсутствие старого мастера, три цикла запуска/закрытия; отдельный настоящий скриншот интерфейса из Windows CI.
4. Локальная модель: строгая интерпретация текущего процесса, отказ чужому PID, отсутствие статуса «интернет восстановлен» после одного лишь старта фильтра и приватность `latest-support.json`.

**Статус до полевой приёмки:** `DIRECT_NATIVE_DRY_RUN_QUALIFIED` после успешного Windows CI; `REAL_NETWORK_NOT_ACCEPTED` до реального испытания WinDivert на пользовательской сети.
