# Bypass Manager 0.3 Alpha

Автономный интерфейс Windows для **адресной экспериментальной DPI-обработки внешнего транспорта**. Не VPN и не сетевой прокси. Работает с **отдельно запускаемым** VPN-клиентом; не управляет его профилями, ключами, подключениями или маршрутизацией.

**Статус: EXPERIMENTAL / NOT_ACCEPTED.** Наличие Windows EXE и Linux PASS не доказывает совместимость с WinDivert, настоящим VPN-handshake или работоспособность в какой-либо конкретной сети. Тестовые стратегии не гарантируют доступ к недоступному входному IP.

## Исправления диагностики на основе полевого отчёта

- **Никаких мигающих окон PowerShell:** дочерние системные проверки выполняются со скрытым консольным окном (`CREATE_NO_WINDOW`), а оригинальный `winws2` запускается со скрытым окном и раздельными локальными журналами. Это не влияет на окно самого Bypass Manager.
- **Правильный объект маршрута:** `Find-NetRoute` возвращает два объекта (адрес интерфейса, затем маршрут). Программа теперь выбирает исключительно объект с `DestinationPrefix`, а не первый объект с `InterfaceAlias`. Ранее это могло давать ложный `маршрут не подтверждён` на действующем компьютере.
- **При отсутствии маршрута тест прекращается:** статус `ROUTE_PRECHECK_BLOCKED`, ни одна следующая стратегия (`UDP-FAKE`, `UDP-REPEAT` и др.) автоматически не запускается. В отчёте сохраняется классификация `NO_ROUTE` или `LOOKUP_ERROR`, без адреса узла и локальных путей.
- **Безопасная отмена:** исправлена гонка остановки контрольного таймера, которая могла пропускать очистку собственного фильтра при одновременной отмене.
- **Два разных IP:** поле «IP VPN-сервера» означает *реальный адрес удалённого узла Amnezia, к которому обращается клиент*. Это НЕ публичный IP, наблюдаемый сайтами. Контрольный внешний IP до VPN не обязан изменяться, если VPN не подключился. Только VPN-провайдер или согласованный прокси назначает действительные выходные адреса. Нельзя генерировать случайные «неиспользуемые» адреса и направлять на них пакеты.
- **Пул узлов:** не реализован в Alpha. Для Amnezia Premium актуальные серверы следует получать через поддерживаемое провайдером обновление конфигурации, не через сканирование чужих адресов. Переключение узла требует совместимого сервера, подтверждённого маршрута и обычно нового подключения; бесшовная ротация существующих TCP-сессий без управляемого промежуточного слоя не обещается.

Если повторяется `ROUTE_PRECHECK_BLOCKED`, сначала отдельно проверьте подключение Amnezia, фактический IP/порт выбранного узла и Kill Switch. Не включайте экспериментальную DPI-обработку при неизвестном или неподтверждённом сервере.

## Автоматический IP и порт Amnezia Premium

**В основном сценарии не нужно искать и вводить IP/порт сервера Amnezia**. Они могут не отображаться в официальном клиенте и не являются едиными постоянными адресами для всех подписок.

При необходимости DPI приложение пытается найти *фактический внешний транспорт текущего VPN* без чтения конфигураций или ключей: AmneziaWG через установленную нативную `awg.exe` с проверкой имени VPN-адаптера либо имеющиеся разрешённые события Windows WFP; VLESS через два согласованных снимка TCP-сокетов доверенного XRay-процесса. Проверяется физический маршрут и свежесть наблюдения. После переподключения IP/порт проверяются повторно. Если Windows не даёт достаточных свидетельств, DPI-опыт пропускается, но диагностика соединения без DPI остаётся доступной. Командные строки, ключи, подписки и адреса из памяти не попадают в экспорт отчётов.

Функция зависит от того, какие нативные компоненты Amnezia Premium установлены и разрешён ли уже аудит Windows. Обычный `Get-NetUDPEndpoint` не показывает удалённый UDP-сервер. Без такого источника программа не может гарантировать определение AmneziaWG endpoint и не подставляет выдуманные IP. Маршрут и внешний IP программы не доказывают handshake, а внешний IP каждой Windows-программы ещё требует отдельной проверки.

## Последовательный мастер AmneziaWG / VLESS и подробная диагностика

Главная кнопка теперь **«Автоподбор VPN и видео»**. Она выполняет
фиксированный, воспроизводимый сценарий. Два протокола Amnezia Premium
рассматриваются **отдельно**: сначала AmneziaWG, затем, только при отсутствии
подтверждённого пригодного соединения, VLESS. При переключении протокола
программа показывает одно конкретное действие в официальном окне Amnezia.
Самостоятельно изменять настройки, ключи, подписку или выбранную локацию
Amnezia приложение не умеет и не пытается. Наличие маршрута/адаптера
не означает доказанного VPN-handshake.

Порядок вариантов (автоматическая очередь, по одному):

1. `AmneziaWG / NONE` (без DPI).
2. `AmneziaWG / UDP-FAKE` и `UDP-REPEAT` (только с актуальным подтверждённым
   внешним сервером, портом и физическим маршрутом; иначе автоматически
   пропускаются).
3. Пользователь один раз переключает **AmneziaWG -> VLESS** по инструкции.
4. `VLESS / NONE` (без DPI).
5. `VLESS / TLS-SPLIT`, `TLS-DISORDER`, `TLS-FAKESEQ`, `TLS-FAKETTL`
   только при подтверждённом сервере и соответствующем TCP-транспорте;
   параметры от AmneziaWG не переиспользуются и не угадываются.

Перед каждым DPI-профилем программа попросит отключить VPN, проверит отсутствие
рабочего VPN-маршрута, включит **только свой** WinDivert-фильтр и попросит
подключиться. Сам DPI-профиль и порядок выбираются автоматически.
Активный тест не может бесконечно ждать: действует защитный таймер и
принудительное снятие собственного фильтра при отмене или сбое.
Переход к следующему протоколу не выполняется, пока не завершён/пропущен
предыдущий. Подтверждённо работающий веб-доступ не отключается для
бессмысленного перебора DPI только из-за ошибки сервиса определения IP.

### Надёжность измерений и отчёт

Для скорости нужны четыре полные загрузки по 2 МиБ, а не просто HTTP 200.
Если основной тестовый HTTPS-сервер не отвечает, автоматически проверяется
альтернативный сервер с поддержкой **HTTP Range 206**; при отказе `Range`
скачивание большого файла не продолжается. Неполная загрузка и недоступность
обоих тестовых серверов отображаются как **«скорость не измерена»**, а не
как 0 Мбит/с. Даже четыре успешные загрузки не гарантируют беспрерывного
видео: необходимо дополнительно проверить реальное воспроизведение не менее
15 минут. Показатель внешнего IP и счётчики VPN-адаптера оцениваются отдельно.

Кнопка **«Открыть отчёт»** теперь открывает
`%LOCALAPPDATA%\BypassManager\results\latest-guide.json` с полной
последовательностью `events`, `rounds` и `monitor_samples`: время и код каждого
перехода, заявленный протокол и DPI-профиль, применимость endpoint,
наблюдение маршрута, результаты каждого независимого IP-сервиса без самого IP,
объём, длительность, скорость каждой HTTPS-загрузки и классификацию отказа.
Случайные сетевые ошибки/URL/локальные пути не копируются в отчёт. Отчёт
перезаписывается и в ходе работы, а не только после завершения. Для передачи
разработчику используйте именно JSON; реальные VPN-ключи не нужны.

**Ограничение автоматического определения:** если Windows не предоставила подтверждённый внешний адрес и порт VPN-сервера
экспериментальная DPI-обработка пропускается. Восстановить их из названия
адаптера Amnezia Premium достоверно нельзя. Публичного подтверждённого API
управления всеми подключениями Premium нет. Программа не сканирует чужие
адреса и не генерирует поддельные серверы. CI проверяет исходники, интерфейс
и исходные Lua без реального VPN-перехвата. Полевой результат остаётся
`NETWORK_NOT_ACCEPTED` до фактической работы в пользовательской сети.

## Возможности интерфейса

- Нативное окно Win32: основная кнопка **Автоподбор VPN и видео**, автоматическое обнаружение VPN-состояния, HTTPS-проверка, восстановление собственного DPI, диагностика DNS, журнал. Технические адрес/порт/транспорт и подбор DPI скрыты в дополнительных настройках.
- Последовательный подбор: **NONE (контроль без DPI)** → ранее подтверждённая стратегия → приоритетная стратегия → остальные стратегии подходящего транспортного класса.
- Проверка измерений: 2 из 3 источников выходного IPv4, загрузка 128 КиБ и 1 МиБ по HTTPS, рост Rx/Tx указанного VPN-адаптера, **подтверждённый маршрут к внешнему IP** и два последовательных успешных измерения. Эти условия показывают *наблюдаемый IPv4-путь данных*, но не доказывают нативный VPN-handshake.
- **Проверка риска IPv6:** сравнение публичного IPv6 до/после включения VPN двумя из трёх HTTPS-сервисов. Совпадение публичного IPv6 помечается как `POSSIBLE_IPV6_BYPASS`. При отсутствии ответа или изменении IPv6 **отсутствие утечек не заявляется**. Пассивная диагностика DNS-маршрутов Windows выполняется отдельно; фактические DNS-запросы, WebRTC и отпечаток браузера не проверяются.
- **Диагностика DNS:** кнопка **Проверить DNS** доступна без начала автоподбора. Укажите точное имя уже подключённого VPN-адаптера, затем нажмите кнопку. Проверка читает настройки DNS и текущие маршруты Windows, не отправляет DNS-запросы, не меняет DNS или VPN. Маршрут к DNS вне VPN означает *потенциальный риск*, но не подтверждённую утечку.
- **IPv6:** HTTP-клиент теперь принудительно использует `tcp6`; успешный HTTP через `tcp4` не может подменить результат проверки IPv6.
- Мониторинг после успеха каждые 45 секунд; при трёх последовательных сбоях стратегия лишается статуса подтверждённой, запускается проверка следующей. Подробные измерения ограничены **последними 512 пробами**, чтобы программа могла работать долго без неограниченного роста журналов.
- Перед сменой стратегии приложение **попросит пользователя отключить/подключить VPN самостоятельно**. Без нового рукопожатия исход изменённого DPI-профиля нельзя измерить достоверно.
- Оригинальные компоненты zapret2 скачиваются только **после согласия**, из закреплённого публичного коммита (только 7 необходимых файлов), с проверкой Git blob SHA-1 при установке и последующих запусках. Не устанавливается Windows-служба и не создаётся автозапуск.

## Два приложения, один локально управляемый движок

Отдельно устанавливать **Zapret как программу или службу** не требуется.
Bypass Manager запускает оригинальный `winws2` с его Lua-модулями и WinDivert **в качестве внутренних компонентов**; второй пользовательский клиент - отдельно запускаемый VPN. Нельзя удалить или подменить `winws2`, оставив ту же работоспособность: это фактический пакетный движок DPI-обработки.

Доступны два способа подготовки:

- **Автоматический:** при первом автоподборе **только если контроль NONE не подтвердился** и с подтверждением пользователя получает семь неизменённых файлов оригинального проекта и проверяет их контрольные суммы. Контроль без DPI не требует движка. Файлы устанавливаются в `%LOCALAPPDATA%\BypassManager\engine`, без службы и автозапуска. Требуется доступ к официальному источнику при подготовке.
- **Портативный/офлайн:** заранее разместите семь оригинальных файлов в каталоге `engine/` **рядом с `Bypass-Manager.exe`**, сохранив подпапку `lua/`. Если хеши соответствуют закреплённому коммиту, программа обнаружит каталог автоматически и не станет ничего скачивать. Это особенно полезно для запуска там, где первичный доступ к GitHub ограничен. Бинарники третьей стороны не вшиваются в наш EXE.

Пути с пробелами (например, имя пользовательского профиля Windows) поддерживаются при запуске оригинального `winws2`. Не отключайте Windows Defender, UAC или другие системные средства защиты для установки.

## Запуск

0. **До использования в ограниченной сети:** запустите EXE, нажмите **Подготовить движок** и подтвердите загрузку семи проверяемых файлов. VPN-подключение и адрес узла для этой операции не нужны. На компьютере с уже подготовленным портативным `engine/` кнопка только проверяет хеши без сетевого обращения.
1. Установите официальный VPN-клиент и создайте в нём рабочую конфигурацию. **Не передавайте программе ключи, конфигурационные файлы или подписки**.
2. Распакуйте релизный `Bypass-Manager.exe` в выбранный каталог. Запустите двойным щелчком. Windows запросит UAC для операций с WinDivert. В тестовой версии нет издательской подписи.
3. **Только в расширенном ручном режиме** укажите **точный внешний IPv4 и порт VPN endpoint**, если у вас уже есть подтверждённые параметры; основной мастер определяет их автоматически при наличии системных данных. Не используйте адрес сайта, заданный как SNI/serverName. Выберите `AWG-UDP`, `REALITY-TCP` или `XHTTP-TCP` только если именно такой транспорт предоставляет ваш VPN-сервис. Для XHTTP/TCP обязательно реально используемое TCP-подключение.
4. В поле движка по умолчанию `%LOCALAPPDATA%\BypassManager\engine`. Если файлов нет, подтвердите получение оригинального Windows bundle. При недоступности GitHub положите вручную оригинальные файлы `winws2.exe`, `WinDivert.dll`, `WinDivert64.sys`, `cygwin1.dll` и Lua `zapret-lib.lua`, `zapret-antidpi.lua`, `zapret-auto.lua` в этот каталог с подпапкой `lua`.
5. Нажмите **Автоподбор**. Когда появится запрос, отключите VPN в стороннем клиенте и подтвердите действие. После сбора контроля программа покажет запрос подключить VPN обратно. Повторяйте только действия, которые предлагает программа при переходе к следующему профилю.
6. Для остановки нажмите **Остановить**. Дождитесь завершения; процесс `winws2` останавливается только после сверки PID, пути и времени запуска. Чужие VPN и DPI-процессы программа не выключает.

Состав тестовых профилей: `NONE`, `UDP-FAKE`, `UDP-REPEAT` для AWG-UDP; `NONE`, `TLS-SPLIT`, `TLS-DISORDER`, `TLS-FAKESEQ`, `TLS-FAKETTL` для TCP. `repeater` используется только со штатным `zapret-auto.lua`. Все варианты, кроме NONE, **экспериментальны**.

## Данные и воспроизводимость

При проверках приложение обращается к **внешним HTTPS-сервисам определения IP** (включая IPv4 и IPv6) и к тестовому сервису загрузки. Эти сервисы видят соответствующий исходящий адрес. Секреты VPN клиенту тестирования не передаются. `POSSIBLE_IPV6_BYPASS` означает риск, а не подтверждённый источник утечки. Отсутствие предупреждения **не является** сертификатом анонимности.

`%LOCALAPPDATA%\BypassManager\settings.json` содержит необходимый для работы endpoint, порт, тип транспорта, путь движка, предпочтение и идентификатор VPN-адаптера. Это **только локальный файл**, который нельзя включать в публичный репозиторий. Хранение ключей не предусмотрено. Диагностические отчёты расположены в `results/latest-session.json`, IP-адреса и имена адаптеров в отчётах удаляются. Произвольные ошибки сетевых загрузок в отчётах заменяются категорией `NETWORK_ERROR_REDACTED`; IP и имена интерфейсов не выгружаются. Тем не менее при публикации любых локальных отчётов предварительно просмотрите их. Файлы процесса `active/` и журналы оригинального winws2 остаются локальными и могут содержать технические сведения сети.

## Что доказывают тесты

- `go test -race ./...` на Linux: структура профилей, правила выбора, проверка IPv4, подсистема загрузки, проверка встроенных ресурсов, редактирование отчётов, подлинность закреплённых upstream файлов в локальных фикстурах.
- `GOOS=windows ... go build`: создание файла PE32+ GUI x64 **без исполнения**.
- Windows CI: синтаксис PowerShell, нативные Go-тесты, проверка запуска CLI-функции, запуск и закрытие нативного GUI-окна, компиляция точного WinDivert-фильтра через официальную DLL без загрузки драйвера, `winws2 --dry-run` и `--intercept=0` со штатными Lua. **Это не проверяет работу самого фильтра на живом трафике**.
- Полевое испытание: Windows GUI + настоящий внешний VPN + контроль NONE и измерения каждой стратегии на одной сети. Отдельно нужны свежий native-handshake, реальные счётчики, 30+ минут, повторные подключения, скорость, потери, холодный перезапуск Windows. Эти испытания **не выполняются в публичном CI**, где нет разрешённой VPN-конфигурации и соответствующего подключения.

Ни Steam Datagram Relay, ни загрузочные сервера Steam не используются как чужая прокси-инфраструктура. Копирование UDP-формы игрового обмена не равнозначно настоящему аутентифицированному игровому протоколу.

Оригинальные проекты: [zapret2](https://github.com/bol-van/zapret2), [zapret Windows bundle](https://github.com/bol-van/zapret-win-bundle), [Amnezia](https://github.com/amnezia-vpn), [Xray](https://github.com/XTLS/Xray-core). Упакованные сторонние бинарники в исходниках и архиве менеджера отсутствуют.

См. [RESEARCH-TRANSPORTS-2026-RU.md](RESEARCH-TRANSPORTS-2026-RU.md) и [PRIVACY-PROXY-DESIGN-RU.md](PRIVACY-PROXY-DESIGN-RU.md). ## Диагностика компьютера и сети: итерация 0.3.2

**Главная кнопка «Диагностика сети»** собирает локальный снимок состояния Windows **без изменения настроек**, сохраняет `%LOCALAPPDATA%\BypassManager\results\latest-network.json` и выводит конкретные коды проблем в журнал. Отчёт «Открыть отчёт» теперь открывает самый свежий из `latest-network.json`, `latest-guide.json` и `latest-session.json`.

Снимок включает: число активных физических и виртуальных VPN-интерфейсов, тип основного подключения (Wi-Fi/Ethernet/другое), скорость локального линка, необязательный уровень Wi-Fi-сигнала, MTU и метрики IPv4 физического интерфейса и VPN, наличие полного маршрута IPv4 VPN, факт включения пользовательского системного прокси, накопленные счётчики ошибок и отброшенных пакетов. Никакие SSID, BSSID, MAC, IP, адреса DNS и шлюзов, прокси-URL, географические и провайдерские названия или локальные пути в публичный отчёт не входят. В интерфейсе возможны статусы «неизвестно», а не вымышленные данные.

При нажатии **«Автоподбор VPN и видео»** снимок сети автоматически сохраняется **перед контрольным испытанием, в начале каждой попытки и после передачи тестовых данных** как `network_diagnostics` в `latest-guide.json`. Только при нескольких измерениях имеет смысл сравнивать изменение счётчиков ошибок и отбросов; абсолютные показатели с момента запуска адаптера не доказывают потери при текущем испытании. Если во время эксперимента меняется тип или скорость физического линка, данные не считаются сравнимыми.

Потенциальные рекомендации: улучшить слабый Wi-Fi/проверить Ethernet, проверить нестабильный локальный линк, неоднозначные маршруты и активные VPN-адаптеры, штатный системный прокси, MTU и раздельное туннелирование. Все это **гипотезы**, которые проверяют сравнительными испытаниями. **Менеджер не отключает антивирус, брандмауэр, IPv6 или Kill Switch и не изменяет DNS, MTU, метрики, маршруты, драйверы или настройки провайдера автоматически.**

Следующая очередь испытаний для подтверждения причины: контроль без VPN; состояние физического соединения; реальный VPN-путь/доступность нескольких HTTPS-сервисов; DNS и разрешение имён; реальные потери/задержка/jitter (с отдельным согласием на активные сетевые пробы); MTU/PMTU; 10–15 минут реального видео. Это не одно «магическое» переключение. Перед каждой допускаемой коррекцией необходимо сохранять исходные параметры, менять одну настройку, сравнивать скорость и стабильность, автоматически возвращать прежнюю настройку при ухудшении.

Windows PowerShell 5.1/Windows Server 2022 проверяет исходный скрипт через `Tests/Test-NetworkHealth.ps1`; запуск на реальном пользовательском устройстве, факт активной маршрутизации через VPN и качество видео остаются отдельной полевой проверкой.

### Фазы HTTPS и принятие решений

В подробном `latest-guide.json` каждая попытка загрузки теперь включает только **числовые** длительности `dns_ms`, `tcp_connect_ms`, `tls_ms`, `time_to_first_byte_ms`, а также `http_status`. Это позволяет отличать задержку разрешения имён, установления TCP, согласования TLS и ответа тестового сервера от низкой скорости передачи тела файла. Поля могут быть нулевыми, если соответствующая фаза не происходила/не была наблюдаема; ноль сам по себе не свидетельствует о мгновенном соединении.

Для диагностики качества сети по-прежнему требуется сравнение состояния без VPN и с VPN на одном физическом интерфейсе, нескольких независимых HTTPS-источников и фактического видео на целевом сервисе. Один быстрый тест или один неответивший CDN не доказывает состояние провайдера или DPI. Менеджер не меняет системную маршрутизацию автоматически и не генерирует чужие VPN endpoint-адреса.

## Экран 0.3 Alpha: наблюдаемый IP, скорость и устойчивость (доработка 16.11.2026)

**«Выход / скорость»** работает независимо от DPI-перебора. Только после согласия пользователя он обращается к трём HTTPS-сервисам для получения внешнего IPv4. Адрес признаётся наблюдаемым при согласии не менее двух источников. Затем выполняется геолокация через `https://ipapi.co/json/` либо резервный `https://ipwho.is/`: страна, регион, город и ASN отображаются **только локально в главном окне**, причём только если сервис геолокации вернул ТОТ ЖЕ IPv4. Геолокация по IP приблизительная и не устанавливает физическое местонахождение человека.

Для сравнения выхода **сначала отключите Amnezia** и однократно нажмите «Выход / скорость». Если Windows однозначно показывает отсутствие активного VPN-адаптера, локально сохраняется приватный эталон `%LOCALAPPDATA%\BypassManager\private-direct-baseline.json`. После подключения Amnezia повторите проверку. Если исходный и текущий IP совпадают, вы увидите предупреждение о возможном прямом выходе; если отличаются, это НЕ доказывает, что браузер тоже использует VPN. Эталон старше 6 часов признаётся устаревшим. При сомнении программа пишет «Не проверено», не имитируя подтверждение защищённости.

**Скорость:** один разогревающий тест 2 МиБ и два адаптивных (от 2 до 32 МиБ). Не более 66 МиБ ожидаемой полезной нагрузки за одно нажатие. Для каждой попытки используются два независимых HTTPS-источника с переходом на резерв при ошибке первого. Показываются худшая и медианная скорость полных загрузок, а не номинальная скорость Wi-Fi или цифра от оператора. Результат `SPEED_NOT_VERIFIED` означает отсутствие достаточного числа измерений, а не 0 Мбит/с. Кнопку можно нажать снова в любой момент без переподключения VPN. Текущая проверка может временно потреблять пропускную способность и влиять на видео.

Результат быстрого замера экспортируется в `results/latest-speed.json`. IP/регион/провайдер **не сохраняются в этот JSON**. В нём остаются только статусы, скорость, независимые HTTPS-пробы и сравнение с исходным IP. Локальный файл приватного эталона ни в один общий отчёт не включается. **Адрес, который увидела программа, не гарантирует, что браузер, WebRTC или приложение с собственным прокси имеют такой же маршрут.**

**«Задержка / MTU»** отправляет по согласию пользователя ограниченное число ICMP-запросов до текущего шлюза и внешнего контрольного узла. Сохраняются только число ответов, медиана, p95, разброс задержки и результаты проб DF 1200/1400. Файл `results/latest-path.json` не содержит адрес шлюза или сетевые идентификаторы. Отсутствие ответа может означать фильтрацию ICMP, **не** достоверную потерю пакетов либо проблему MTU. Настройки системы не изменяются.

**«Тест видео: 15 мин»** предназначен для фактического воспроизведения видео в выбранном пользователем браузере. Нажмите кнопку, откройте реальное видео и подтвердите начало: каждые 30 секунд менеджер фиксирует наличие VPN-маршрута, изменение счётчиков адаптера и небольшую HTTPS-пробу. Каждая четвёртая проба содержит 2 МиБ и позволяет увидеть ухудшение скорости в процессе. По окончании 15 минут программа попросит указать, были ли остановки видео. Обзор реального видеоплеера **не автоматизирован**: пользовательское наблюдение обозначено отдельно, HTTPS-пробы не приравниваются к метрикам браузерной буферизации. Прерванный тест не признаётся успешным. Результат пишется на диск после каждой пробы в `results/latest-stability.json`.

Кнопка **«Собрать отчёт»** создаёт `results/latest-support.json` со всеми доступными и проверенными отчётами (автоподбор, сеть, ICMP, скорость и стабильность), их возрастом и перечнем диагностических гипотез с последовательностью испытания и отката. Это **единственный файл, который обычно нужно передавать разработчику**. Сырые файлы настроек, приватный эталон, IP, SSID, имена адаптеров, имена пользователей и VPN-ключи в сводный отчёт не включаются. Файлы устаревших или неизвестных форматов пропускаются.

**Изменение настроек Windows:** диагностика формирует рекомендации и контрольные показатели сравнения, но НЕ применяет MTU, маршруты, DNS, драйверные параметры, правила безопасности или прокси автоматически. Автоматическая запись опасна без гарантированного восстановления после аварийного завершения и подтверждения на целевой Windows-машине. Режимы активного обратимого изменения параметров остаются отдельным не принятым этапом; в публичной Alpha лишь собирается фактическая база для них.

Источники спецификаций: `https://ipapi.co/api/`, `https://ipwhois.io/documentation`, `https://learn.microsoft.com/en-us/powershell/module/netadapter/get-netadapterstatistics`.


## Приложения Windows и временная MTU-проба (доработка 0.3.4)

**«Программы / соединения»** выполняет только чтение активных TCP-соединений Windows
(`Get-NetTCPConnection`) и привязанных UDP-сокетов (`Get-NetUDPEndpoint`).
По локальному IP TCP можно предположить физический интерфейс или интерфейс VPN.
Однако это **не подтверждает внешний IP приложения**: браузерные расширения,
собственный прокси программы, перенаправление на локальный сервис,
WFP-драйверы и раздельное туннелирование могут давать другую картину.
UDP-сокет не содержит проверенного удалённого пути. Названия запущенных программ
показываются только в локальном окне, **не записываются в общий JSON**.
Сводка `results/latest-apps.json` содержит лишь категории и счётчики.
Проверка одной программы не доказывает поведение всех остальных.

**«Проба MTU с откатом»** работает только после явного подтверждения. Испытание
доступно лишь при одном однозначно активном физическом IPv4-интерфейсе
с маршрутом по умолчанию; никогда не изменяет MTU VPN-адаптера, DNS, маршруты,
IPv6, драйверы, Kill Switch или параметры брандмауэра. После исходной полной
HTTPS-загрузки программа может на время уменьшить MTU физического интерфейса
на 80 байт и выполнить повторную загрузку того же размера с того же источника.
Изменение применяется только к `ActiveStore` и **в любом случае откатывается**
после испытания. Перед применением запускается независимый PowerShell-watchdog,
который пытается восстановить исходный MTU в пределах 90 секунд после сбоя GUI.
Перезагрузка Windows должна сбрасывать временный `ActiveStore`.
Это best-effort защита: если и программа, и watchdog аварийно прекращены,
абсолютный откат без внешней приёмки гарантировать невозможно.
Если возникла ошибка отката, программа явно сообщает о ней, а
`latest-mtu-trial.json` сохраняет числовые значения без идентификаторов сети.
Ни кратковременный прирост скорости, ни успешный ping не разрешают автоматически
сохранять MTU постоянно; такой вывод требует нескольких независимых проб.

**Что намеренно не изменяется автоматически:** DNS-серверы, метрики маршрутов,
раздельное туннелирование, TCP auto-tuning, сетевые фильтры, драйверные функции
RSS/offload и настройки безопасности. Для них нет подтверждённого безопасного
сквозного A/B маршрута с отказоустойчивым откатом; текущие проверки дают
диагностику и рекомендации, а не притворяются успешной оптимизацией.

В `latest-support.json` добавлены две обезличенные секции: `apps`, `mtu_trial`.
IP и геолокация остаются исключительно локальными данными экрана
«Выход / скорость». Для проверки приложения, у которого есть собственный
прокси или VPN, внешний адрес нужно проверять **внутри того же приложения**,
а не переносить IP браузера на все программы Windows.
