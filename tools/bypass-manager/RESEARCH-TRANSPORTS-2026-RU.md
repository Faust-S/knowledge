# Bypass Manager 0.3 Alpha. Исследование транспортов и приватности

Актуализация: 16.11.2026. Тип материала: сравнительный инженерный анализ, **не результаты проверки обхода на целевой сети**. Географических данных, данных пользователей и адресов действующих VPN-узлов здесь нет.

## 1. Главный принцип

Малоизвестность протокола сама по себе не повышает устойчивость: нестандартная реализация может оставлять более редкий и характерный отпечаток, чем популярный HTTPS-клиент. В частности, важны: реальный протокол на проводе, поведение при активном зондировании, блокировки IP/ASN, статистика долгих соединений, совместимость клиента **и сервера**.

В нашей архитектуре **отдельный VPN-клиент** владеет туннелем, шифрованием, ключами, DNS и маршрутизацией. Bypass Manager может применять адресную обработку внешних пакетов через оригинальный winws2, измерять внешние результаты и сообщать об ограничениях. Он не способен односторонне превратить AWG-сервер в сервер XHTTP, MASQUE или Tor. Результат HTTPS-загрузки сам по себе не является доказательством отсутствия утечек DNS/IPv6 или анонимности.

## 2. Таблица для архитектурных решений

| Направление | Что даёт | Что требуется извне | Решение сейчас |
|---|---|---|---|
| AmneziaWG 3.1 | Динамические заголовки и поведение UDP, криптография WireGuard | Настоящий AWG 3.1 сервер, разрешённая конфигурация в отдельном клиенте | Основной опытный маршрут. Сравнение `NONE` с UDP-профилями winws2. Положительный полевой результат **не получен** |
| `winws2` TLS split / disorder / fake | Меняет начальные TLS-пакеты для некоторых видов DPI | Уже существующий TLS/TCP туннель, корректный внешний IP и порт | Адресный эксперимент поверх отдельно работающего TLS-клиента. Не поможет, если IP целиком заблокирован |
| XHTTP + REALITY (Xray) | Разнообразные формы TLS/HTTP обмена | Совместимая конфигурация Xray на обеих сторонах | Нельзя включить из GUI одной галочкой на AWG-сервере; держать как отдельный серверно-поддержанный маршрут |
| Hysteria 2 (HTTP/3 / QUIC, Salamander / Gecko) | QUIC-передача и дополнительные механизмы против распознавания пакетов | Совместимый Hysteria 2 клиент и сервер, работающий UDP | Перспективное исследование при наличии endpoint, не подменять повторителем UDP из winws2 |
| NaïveProxy | Стек Chromium для сетевого сходства с обычным HTTPS/HTTP/2 | HTTP-прокси сервер и поддерживаемый фронтенд, отдельный клиент | Перспективный отдельный путь, не локальная опция существующего AWG |
| Tor WebTunnel / obfs4 / Snowflake | Мосты Tor, резервные пути доступа, усиленная браузерная приватность | Tor Browser, работающие транспорты/мосты | Для анонимного браузинга использовать специализированное ПО, не пытаться незаметно переключать пользовательские приложения |
| MASQUE / CONNECT-UDP (RFC 9298) | Стандартная туннелизация UDP через HTTP | Поддерживаемый сервер HTTP CONNECT-UDP и клиент | Архитектурная гипотеза на будущее. Без совместимого прокси не выполняется |
| ECH (RFC 9849) | Шифрование части TLS ClientHello, включая внутренний SNI | Поддержка сервисом, ECHConfig, совместимый DNS | Положительно для конфиденциальности TLS, но **не скрывает серверный IP**, не заменяет VPN |
| Conjure / refraction | Новый путь доступа через сотрудничающую сеть | Специальная инфраструктура оператора/станции | Исследовательское направление, не применимо как локальная DPI-галочка |

## 3. Практическая расстановка приоритетов

1. **Подтверждение существующего AWG/TCP без подмены сервера**: диагностика маршрута к внешнему узлу, два успешных испытания передачи данных, проверка счётчиков того же адаптера, отделение ошибки IP-блокировки от ошибки DPI.
2. **Утечки**: независимая проверка IPv6 с сравнением до/после. Совпадение публичного IPv6 по нескольким источникам — предупреждение о *возможном* обходе туннеля; отсутствие IPv6-ответа или новый адрес не доказывают приватность. DNS, WebRTC, отпечаток браузера и аккаунты **не проверены**.
3. **Правильные границы профилей**: UDP-профили только при реальном UDP-транспорте, TLS-профили только при реальном TLS/TCP-транспорте. Не создавать «рекомендованные» недоступные транспорты.
4. **Долговечность**: ограниченный по памяти журнал, корректное восстановление и остановка только собственного процесса, без автоматического вмешательства в сторонний VPN.
5. **Полевые испытания**: воспроизводимые серии контроль → профиль → VPN handshake → HTTPS-загрузка → долгий поток → повторные подключения. Лабораторная проверка аргументов winws2 не доказывает обход.

## 4. Почему не имитация Steam

Игровые соединения не являются одним универсальным протоколом: построить пакеты с похожими размерами недостаточно для действительной аутентифицированной игровой сессии. Невозможность поддержать поведение настоящего игрового сервиса сделает имитацию отдельным узнаваемым маркером. Не использовать чужие игровые серверы как выходные узлы; не заявлять маскировку под них без совместимого протокола и экспериментальных доказательств.

## 5. Область анонимности

- VPN и DPI-обфускация главным образом относятся к доступности/сокрытию характера соединения от локальной сети. VPN-провайдер остаётся отдельной стороной доверия; сайты и аккаунты продолжают идентифицировать пользователя.
- Отсутствие IPv6-утечки при одной проверке нельзя объявлять доказанным: измерения могут не выполняться из-за фильтрации сервисов.
- DNS, IPv6, WebRTC, TLS-отпечаток клиента, веб-отпечаток устройства, загрузки вне туннеля и корреляция по времени требуют **раздельных** тестов и угрозной модели.
- Tor Browser имеет собственные антифингерпринтинговые меры. Использовать обычный браузер через Tor или совмещать Tor с VPN автоматически не следует.
- Настройки, ключи, идентификаторы пользователей и сырые сетевые логи не публикуются. Публичные отчёты менеджера должны содержать только обезличенную диагностику.
