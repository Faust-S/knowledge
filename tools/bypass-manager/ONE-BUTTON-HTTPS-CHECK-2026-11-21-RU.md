# Bypass Manager 0.4: контроль доступности при включении и автономный запуск

## Исходный дефект

В версии One Button GitHub Actions подтверждал, что собственный процесс `winws2` запускается и останавливается, однако после включения программа не проверяла, может ли она получить данные через HTTPS. При отсутствии доступа к GitHub первый запуск вообще мог не состояться из-за отсутствия оригинальных семи компонентов движка. При этом пользователь видел «Включено», хотя доступность нужного ресурса оставалась неизвестной.

## Реализованный контроль

После нажатия «Включить» приложение проверяет три заранее выбранных общедоступных HTTPS-сервиса **до** запуска фильтра и повторяет те же проверки **после** запуска. Используются независимые поставщики, HTTPS с проверкой сертификата, только IPv4-путь самого Bypass Manager, свежие TCP/TLS-соединения для каждого измерения, тайм-аут до 7 секунд на сервис и ограниченный объём ответов. Все три проверки выполняются параллельно, поэтому при недоступном интернете результат не задерживает включение на 21 секунду.

Система различает HTTP-ошибку, редирект/подмену captive portal, неверный ответ, тайм-аут и успешный точный ответ. Испытания не загружают пользовательские URL и не исследуют посещённые домены. При включении эти три внешних сервиса **увидят исходящий IP самого приложения**; это явно указано на экране.

Коды результата: `GENERAL_HTTPS_AVAILABLE`, `GENERAL_HTTPS_CHANGE_OBSERVED`, `GENERAL_HTTPS_DEGRADED`, `GENERAL_HTTPS_STILL_IMPAIRED`, `ENGINE_NOT_RUNNING`, `CHECK_INCOMPLETE`, `AFTER_ONLY`. Они описывают **только доступность пробных HTTPS-сервисов**. Даже `GENERAL_HTTPS_CHANGE_OBSERVED` не доказывает влияние DPI, успешный обход конкретного сайта, работу браузера или VPN и не означает, что IP скрыт.

Модель измерений и сроки сохраняются локально в `results/latest-direct-check.json`. Экспорт `latest-support.json` включает только фиксированные `CHECK_A/B/C`, коды ошибок и длительности. Внешние IP, домены сайтов, имя процесса и URL не экспортируются. Подменённые или повреждённые JSON отклоняются.

## Первый запуск без доступа к GitHub

Windows ZIP теперь должен содержать неизменённый оригинальный движок в папке `engine` рядом с EXE. Код сначала проверяет **все семь файлов** по закреплённым Git blob SHA и атомарно переносит их в приватную папку программы. Если пакет повреждён или неполон, приложение отказывается запускать фильтр. Если у разработчика есть только EXE, сохраняется прежний путь одноразового скачивания оригинальных файлов. Поставке сопутствуют лицензии и сведения о происхождении.

## Что этим не решено

Проверки общих HTTPS-сервисов не воспроизводят блокировку конкретного сайта. Для настоящей автоматической оптимизации необходимы дальнейшие измерения на реальных пользовательских соединениях и контролируемая смена стратегий. Не реализована система удалённых VPN-узлов, не гарантировано скрытие IP для всех Windows-программ. Это Alpha, а не окончательная продуктовая приёмка.
